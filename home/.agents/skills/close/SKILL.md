# Close

1. Facts from commands, not memory: python3 <build>/scripts/plan_state.py, where <build> is the build skill's folder (in Claude Code ${CLAUDE_SKILL_DIR}/../build, elsewhere ~/.agents/skills/build), for the branch, HEAD, modified files and the plan; git log --oneline from the merge base with main (falling back to origin/main, then master), and git worktree list. Commands run in this session and their results come from the session itself; name only commands that ran. In a linked worktree the notes are in the main checkout's .private/ (by absolute path; never create .private/ in the worktree).
2. Each plan file the session worked on (for parallel work, every agent's): set Status and Next from the facts (Next is one line a fresh session acts on), the Steps rows with their commits, the Assumptions results, the rulings taken and the dead ends met in this session. The plan's Verification and the log show the gates not run since the last code change: name them in Next when they are owed.
3. No plan file holds this session's work (research, a direct-lane change, an investigation): write .private/handoff/<YYYY-MM-DD>-<slug>.<ext> in the project's prose format and handoff template when it has one, otherwise with: goal, state, files touched, decisions, open questions, refuted assumptions (what, the check, what changed), commands run, commands still needed (each documented gate not run since the last code change), risks, how to check it (for each result, the command or steps and the visible result, marking each that needs a human look), and the code-level facts the next session depends on, marked verify before use.
4. Lessons: for each assumption a check refuted in this session that a rule, a skill or a subagent instruction should have prevented, keep it only if it would change what an agent does next time and no rule already says it. When one command or tool call can detect the mistake, draft the smallest check (a hook, a validation rule, a test, a project lint) whose failure message says what to do instead; otherwise the smallest change to the owning text, with the refuted assumption as its reason. A draft for this project joins step 5 as a Proposed entry; one for the global rules, a global skill, subagent or hook goes into the reply, since the installed copy under ~/.agents is generated from its source repository and is never edited. Nothing changes without the user's approval of the exact text.
5. Decisions: list the decisions of this session that the decision log lacks and that meet its recording bar, and the entries this work left Proposed; ask the user to accept, reject or leave each, and write them by the log's authority rules. Then list the rulings still marked pending, one line each, and record kept or changed for each one the user reviews.
6. Loose ends: the lines added to .private/deferred.<ext> in this session; each linked worktree still open, with its branch and whether that branch has landed (git merge-base --is-ancestor <branch> main); for a landed one, propose its removal as isolated-work section 3 does, and remove nothing without the user's yes.
7. Uncommitted work: list it and ask whether to commit it as the next logical step, leave it or stash it. Never push.
8. Reply opening with one line: Done: yes or Done: no, then one line per request the user made in this session with its state (done with its commit, open with where it is recorded, or the user's). Then the plan paths (or the handoff path) and the single next action as the exact prompt to paste in a fresh session, in a fenced block, for example: run build; it resumes from .private/plans/<slug>.<ext> at <step>.
