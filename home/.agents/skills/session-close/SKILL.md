# Session close

1. Collect facts with commands, not from memory: current branch, git status --short, git log --oneline from the merge base with main (falling back to origin/main, then master) to HEAD, git diff --stat HEAD. Commands run in this session and their results come from the session itself; list only commands that actually ran.
   Read every progress log of the task (for example .private/progress/<slug>*.<ext>, so the per-agent logs of parallel work count), and bring the one this session keeps up to date from these facts: steps and commits since its last entry, decisions taken in this session with who took them, assumptions refuted in this session, and attempts that failed in this session (what was tried, the result, why it was dropped).
2. Fill the project's handoff template when it has one (Goal, Files touched, Decisions, Open questions, Commands run, Commands still needed, Risks, Refuted assumptions, How to check it). Commands still needed must include every documented gate not run since the last code change. Refuted assumptions lists each assumption of this session that a check broke: what was assumed, the check that broke it, what changed. How to check it gives the user, for each acceptance criterion the work meets so far, the command or the steps and the visible result to expect, marking each check that needs a human look.
3. Name the code-level facts the next session will depend on (files, symbols, signatures) and mark them "verify before use": they may change before the next session reads the handoff.
4. Lessons: for each refuted assumption that a rule, a skill or a subagent instruction should have prevented, draft the smallest change to the owning text that would have prevented it, with the refuted assumption as its reason. A draft for a rule of this project joins the decisions of step 5 as a Proposed entry. A draft for the global instructions, a global skill or a global subagent (installed under ~/.agents from their own source repository) goes into the reply; never edit the installed copy. Change no rule without the user's approval of the exact text.
5. Decisions: list each decision made in this session that the decision log does not hold yet and that meets its recording bar, and each entry the task added to the decision log that is still Proposed (the spec and the progress logs name their ids). Ask the user to accept, reject or leave each as Proposed, then write them accordingly (Accepted only when the person the log's authority rules name as decider confirmed it). Then list the progress logs' decisions by agent still marked Review: pending, and record kept or changed for each one the user reviews.
6. Update the handoff's Decisions from step 5, then write the handoff to the project's working-notes location (for example .private/handoff/<YYYY-MM-DD>-<slug>.<ext> when .private/ is git-ignored; otherwise ask once), in the project's prose format.
7. Uncommitted work: list it and ask whether to commit it as the next logical step, leave it, or stash it. Never push.
8. Reply with the handoff path, the progress log paths when there are any, and the single next action, phrased for a fresh session and naming the handoff path (for example: start a fresh session, then run the implement skill on .private/specs/<slug>.<ext> from plan step N, reading .private/handoff/<YYYY-MM-DD>-<slug>.<ext> first).
