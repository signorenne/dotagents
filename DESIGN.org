#+TITLE: dotagents design
#+SUBTITLE: how the pieces compose and install, and the rules that bind
#+OPTIONS: toc:2 num:nil ^:nil
#+STARTUP: showall

This file owns dotagents' design: the public surface, how the pieces compose,
the install model, the hooks' failure model, naming, and the rules that bind
every change. [[file:VISION.org][VISION.org]] owns the direction. [[file:AGENTS.md][AGENTS.md]] owns where each
change goes, the hard rules and the review checklist.
[[file:CONTRIBUTING.org][CONTRIBUTING.org]] owns the workflow and the docs format.
[[file:docs/skill-authoring.org][docs/skill-authoring.org]] owns how a skill is written. [[file:docs/pipeline.org][docs/pipeline.org]]
owns the stages a change goes through. [[file:docs/architecture.org][docs/architecture.org]] draws the
structure, the install flow and a session's runtime view.

North star: change a rule once, run the installer, and every agent in every
tool, and every claude.ai chat, follows the new text.

* Public surface

The global rules say how to work, a skill says how to do one kind of work, a
subagent does one job in a fresh context, and a hook enforces what must not
depend on the model remembering it.

- /Global rules/ : =home/.agents/AGENTS.md=, kept under 200 lines because the
  same text is pasted into claude.ai. They cover priorities, sufficiency,
  evidence, refute before you rely, grounding, decisions, output, learning and
  agentic work, and they bind every skill and subagent.
- /Local skills/ : one folder per skill under =home/.agents/skills/=, with a
  =SKILL.md=, a =LICENSE.txt= and, only where a real run showed the need, a
  reference file, templates or a =scripts/= folder.
- /claude.ai skills/ : one folder per skill under =claude-ai/skills/=, with
  descriptions of at most 200 characters. A local skill also wanted on
  claude.ai gets an entry in =claude-ai/overrides.json= with its short
  description, never a copy; =tools/build.py= swaps that description into the
  zip.
- /Subagents/ : =scout=, =gate-runner= and =reviewer= in
  =home/.agents/agents/=, in Claude Code format (name, description, tools,
  model, and where set effort and color), the source of every other tool's
  copy.
- /Hooks/ : =guard_bash.py=, =after_edit.py=, =session_refresh.py= and
  =compact_brief.py= in =home/.agents/hooks/=, shared by every tool; the
  guard and the after-edit hook learn which tool called them from =--tool=.
- /Claude Code adapter/ : =adapters/claude/settings.json=: read-only git and
  build commands allowed, =git push= denied (also as =git -C <dir> push=),
  =git reset --hard=, =git clean=, =git rebase= and =rm -rf= asked first,
  =.env= files, =~/.ssh= and =~/.gnupg= unreadable, commit and PR attribution
  empty, the synced plugin =engineering@synced= turned off, and the hook
  entries.

* How they compose

** Who loads what

- The global rules load at the start of every session: by the import in
  =~/.claude/CLAUDE.md= in Claude Code, through links in Codex, Gemini CLI,
  Antigravity CLI and Copilot CLI, and by paste in Cursor and claude.ai.
- A skill's description is listed to the model (Claude Code drops the least
  used ones past a budget); its =SKILL.md= loads when a request matches the
  description or the user calls it by name. A reference file next to it loads
  only when the skill says to read it.
- A subagent starts in a fresh context with its own file as instructions and
  its tool list: =scout= read-only, =gate-runner= running commands it does not
  fix, =reviewer= never editing. In Claude Code they run on Sonnet, Haiku and
  Opus, and =gate-runner= starts without the user, project and local
  =CLAUDE.md= files (=omitClaudeMd=), with only its own body and the brief;
  the other tools' copies drop that field. Codex ignores the =sandbox_mode= of
  a custom agent file, so there =scout= inherits the session's sandbox and
  stays read-only only by its instructions.
- Hooks run outside the model, on tool events, and reach it only through what
  they print.

** Skills hand off to each other

The repository workflow is a chain, which [[file:docs/pipeline.org][docs/pipeline.org]] follows stage
by stage. =scoping-before-building= or =architecture-doc= sizes the work;
=spec= writes a self-contained plan and settles each open choice with
=decide=; a fresh session runs =implement= on the spec, which proposes
=isolated-work= for a change across modules, a public API change or a
migration; =implement= ends with the full gates and an independent review;
=session-close= records the state for the next session; on the maintainer's
go, =isolated-work= lands the branch and removes its worktree.

Off the chain: =as-built-docs= sends bugs and anomalies to =code-audit=;
=code-audit= sends a finding the user wants fixed to =implement=, starting
with a failing test; =decision-analysis= researches products and returns a
project's choice to =decide=; =systematic-debugging= comes before
=event-driven-ui= when a freeze is unexplained, and in a repository leaves the
failing test and the fix to =implement=; =parallel-agents= runs each writer
through =isolated-work=; =implement= and the reviewer apply
=trustworthy-tests= to every new or changed test; =context-handoff= gives way
to =session-close= inside a git repository.

** Skills delegate to subagents

- =spec=, =implement=, =project-setup=, =code-audit= and =architecture-doc= map
  the code with =scout= before planning. =as-built-docs= reads the code with
  read-only subagents on the session's model instead (in Claude Code the
  general-purpose subagent, elsewhere the tool's default general agent).
- =gates=, =implement=, =project-setup=, =isolated-work= and =as-built-docs=
  run long commands through =gate-runner=, which reports the commit it tested,
  so only verdicts and first errors reach the conversation; =implement= and
  =isolated-work= also give it the folder and the commit to test, and
  =parallel-agents= gates each branch through =isolated-work=.
- =branch-review=, =implement= and =mechanical-changes= hand the finished change to
  =reviewer=; =parallel-agents= runs implement's review on the merged
  result.
- =spec=, =architecture-doc= and =as-built-docs= verify their documents with a
  subagent that did not write them, and =code-audit= has each finding attacked
  by one briefed only on the claim and the code: in Claude Code the
  general-purpose subagent told not to edit, elsewhere =reviewer=.
- Where a tool has no subagents, the skill follows
  =~/.agents/agents/<name>.md= itself.

** Working notes

Skills keep their working notes in the git-ignored =.private/= folder of each
repository: specs in =.private/specs/<slug>.<ext>=, progress logs in
=.private/progress/<slug>.<ext>=, handoffs in
=.private/handoff/<YYYY-MM-DD>-<slug>.<ext>=, audit reports in
=.private/audit/= and the notes of =as-built-docs= in =.private/as-built/=. A
worktree has no =.private/=, so work in one keeps its notes in the main
checkout's. A project's decisions go to its own decision log, never to working
notes.

* Install model

There is one source, =home/.agents=, installed as =~/.agents=
([[#one-source][one-source]]). =install.py= copies it there, adds the claude.ai set to
=~/.agents/skills/=, then links or generates each tool's files from it.
Nothing is edited in a tool's own folder: a change is made here and the
installer runs again.

| Agent           | Global rules                                                    | Skills                                                      | Subagents                                   | Hooks                                                                                |
|-----------------+-----------------------------------------------------------------+-------------------------------------------------------------+---------------------------------------------+--------------------------------------------------------------------------------------|
| Claude Code     | =~/.claude/CLAUDE.md= imports =~/.agents/AGENTS.md=             | every skill linked in =~/.claude/skills=, synced copies off | =~/.claude/agents=                          | =~/.claude/settings.json=, with PreCompact, and SessionStart after compact or resume |
| Codex           | =~/.codex/AGENTS.md= link                                       | reads =~/.agents/skills=                                    | =~/.codex/agents/*.toml=                    | =~/.codex/hooks.json= (approve in Codex)                                             |
| Gemini CLI      | =~/.gemini/GEMINI.md= link; =context.fileName= adds =AGENTS.md= | reads =~/.agents/skills=                                    | =~/.gemini/agents/*.md=                     | =~/.gemini/settings.json=                                                            |
| Antigravity CLI | =~/.gemini/GEMINI.md= link, shared with Gemini CLI              | =~/.gemini/config/skills.json= lists =~/.agents/skills=     | none                                        | =~/.gemini/config/hooks.json=                                                        |
| Copilot CLI     | =~/.copilot/copilot-instructions.md= link                       | reads =~/.agents/skills=                                    | =~/.copilot/agents/*.agent.md=              | =~/.copilot/hooks/agents-global.json=                                                |
| Cursor          | paste =~/.agents/AGENTS.md= into User Rules                     | reads =~/.agents/skills=                                    | reads =~/.claude/agents= (with Claude Code) | reads the Claude Code hooks (with Claude Code)                                       |

- /Generated, not copied by hand/ : each tool's subagent file is rendered from
  the Claude Code source (TOML for Codex, Markdown for Gemini CLI, =.agent.md=
  for Copilot CLI), with tool names mapped to the tool's own; the Codex copy
  carries the reasoning effort, and the Gemini CLI copy a turn and a time limit
  (=max_turns=, =timeout_mins=) above Gemini CLI's defaults. A skill wanted on
  claude.ai is an override entry, never a second folder.
- /Checked before it starts/ : the installer validates the subagents and the
  JSON sources first and installs nothing when one is broken.
- /Backups/ : every file the installer replaces is moved to
  =~/.agents-backup/<timestamp>/= first; =--dry-run= prints every change and
  touches nothing. A =~/.claude/CLAUDE.md= without the import of
  =~/.agents/AGENTS.md= is replaced by one with it, and the old file is in the
  backup.
- /Idempotent/ : a file whose bytes already match is left alone, so a second
  run changes nothing.
- /Merged settings/ : the Claude Code adapter, Codex's and Gemini CLI's hook
  entries are merged into the tool's settings file: earlier copies of this
  repository's hook entries are removed and the current ones appended, a rule
  the adapter denies is removed from =ask= (where an older install put it),
  and the rest of the file is kept. The adapter also turns off the synced
  plugin =engineering@synced=. Antigravity CLI's hooks file maps hook names to
  events: the installer rewrites its own two names (=dotagents-guard=,
  =dotagents-after-edit=), keeps an =enabled= value set by hand, and adds
  =~/.agents/skills= to the entries of the skills manifest. A file that does
  not parse is left alone with a note to merge it by hand.
- /Antigravity CLI/ : it replaced Gemini CLI for Google AI Pro, Ultra and free
  users on 18 June 2026; Gemini CLI stays for Code Assist licences and paid
  API keys, so both adapters stay. Antigravity CLI gets the guard and the
  after-edit hook but no session refresh, because it documents no event after
  a compaction or a resume, and no subagents yet. It is detected by
  =~/.gemini/antigravity-cli= or the =agy= command.
- /COPILOT_HOME/ : when it is set, Copilot CLI's files go to
  =$COPILOT_HOME= instead of =~/.copilot=, since it replaces that whole path;
  a relative value is refused with a note.
- /Codex rules/ : the installer writes =~/.codex/rules/dotagents.rules=, whose
  =prefix_rule= entries forbid every push and publish the guard blocks. Codex
  writes =default.rules= itself, and the installer leaves it alone.
- /skillOverrides/ : claude.ai syncs its copy of each uploaded skill into
  Claude Code as =anthropic-skills:<name>=, and Claude Code would list it next
  to the local one. The installer sets each of those to =off= in
  =~/.claude/settings.json=; a value set by hand wins.
- /Leftovers/ : a file dropped from a skill folder that still exists goes to
  the backup, as do the legacy items of older versions (their =learn= and
  =handoff= skill copies and the hook copies in =~/.claude/hooks=). A whole
  skill, subagent, hook script or settings entry the repository dropped stays
  installed. =--audit= lists what in the agents' folders does not come from
  here, and broken links, and changes nothing; settings entries are removed by
  hand.

Claude Code is tested end to end. The other tools' files follow their official
documentation, and =tests/test_install.py= checks each generated hook file
against it (events, matchers, tool names, timeouts).

* Hooks and their failure model

| Hook                 | Runs                                            | Tools                                  | Timeout |
|----------------------+-------------------------------------------------+----------------------------------------+---------|
| =guard_bash.py=      | before a shell command                          | all six (Cursor through Claude Code's) | 10 s    |
| =after_edit.py=      | after a file edit or write                      | all six (Cursor through Claude Code's) | 60 s    |
| =session_refresh.py= | at session start after a compaction or a resume | Claude Code, Codex                     | 10 s    |
| =compact_brief.py=   | before a compaction                             | Claude Code                            | 10 s    |

The guard blocks git gate bypasses (=--no-verify=, =commit -n=, hook skip
variables, a disabled =core.hooksPath=) and every push and publish, in every
tool: =git push=, =git subtree push=, =gh pr create=, =gh pr merge=,
=gh release create= and =gh repo sync= ([[#no-agent-push][no-agent-push]]). A push that also
rewrites or deletes published history (=--force= and its variants,
=+refspec=, =--delete=, =:ref=, =--mirror=, =--prune=) and =gh pr merge --admin=
are named as such. The after-edit hook flags em and en dashes in the text just
written and runs clang-format, when the project has a =.clang-format=, on the
lines of a C or C++ file that the edit changed (a newly written file whole).
The session refresh reminds the agent that its picture of the code is a
summary (after a compaction, also to invoke its workflow skill again, since
Claude Code keeps only the start of each skill through one), prints the real
branch, changes and last commits, lists the newest files of
=.private/progress/= and =.private/handoff/=, and asks the agent to re-read the
progress log. The compaction brief tells the summary what resuming needs: the
task and its slug, the branch, the paths of the progress log and handoff, the
current plan step, the decisions marked Review: pending, the files changed and
the commands still needed with their last results; it fills in the branch, the
uncommitted changes and the newest task notes itself.

The hooks share one failure model:

- /Never block on unreadable input/ : a payload that does not parse exits 0,
  so a broken payload never stops normal work. The session refresh never fails
  the session.
- /Never block a compaction/ : exit 2 from a PreCompact hook blocks the
  compaction, and one that recovers from a full context then fails the
  request. The compaction brief always exits 0, and its command ends in
  =|| true= because =python3= itself exits 2 when the script is missing.
- /Block with exit 2/ : the reason goes to stderr, which the agent sees.
  Copilot CLI shows stderr only to the user, so the guard also prints a deny
  decision with the reason on stdout, and the after-edit hook sends its report
  as model context with exit 0. Antigravity CLI documents a JSON reply and no
  exit codes, so there the guard answers a deny decision with the reason and
  exit 0; its after-edit reply is ={}=, which carries nothing to the agent, so
  there the hook formats and exits 0, and its dash report goes only to stderr.
- /JSON only on Gemini CLI's and Antigravity CLI's stdout/ : both read a
  hook's stdout as JSON, so nothing else is printed there. Notices reach the
  model as additional context in each tool's documented format.
- /Finish inside the timeout/ : Claude Code drops all output of a hook that
  times out, so each hook bounds its own work below the configured timeout
  (8 s for the notes listing and the git calls of the session refresh and of
  the compaction brief, clang-format under 60 s); the brief also stays under
  the 10,000 characters past which Claude Code cuts it.
- /Two locks on a push/ : the guard blocks pushes and publishes in every tool,
  and in Claude Code the adapter also denies =git push=, so the permission
  prompt never offers it. In Codex, =~/.codex/rules/dotagents.rules= forbids
  the same commands and holds even while Codex skips hooks the user has not
  trusted yet; Codex calls its rules experimental, and a prefix rule cannot
  see =git -C <dir> push=, which the guard catches.
- /Not a security boundary/ : the guard splits the command as a shell does and
  falls back to a rough split when it does not parse, so a parse error never
  lets a forbidden command through; commands passed as one string (=bash -c=,
  =env -S=, =flock -c=, =git submodule foreach=), =eval=, aliases, scripts and
  =gh api= are not inspected.

* Documentation and skill design

Skills follow [[file:docs/skill-authoring.org][docs/skill-authoring.org]]: concise and complete, a description
that says what and when, one default instead of a menu, progressive
disclosure, and a test in a real session when the maintainer asks for one. The
mechanical rules are the Hard rules of [[file:AGENTS.md][AGENTS.md]]; the docstring of
=tools/validate.py= lists every check it enforces. The docs format is
[[file:CONTRIBUTING.org][CONTRIBUTING.org]]'s, and every doc is registered in [[file:docs/README.org][docs/README.org]].

* Naming

- /Skills/ : lowercase kebab case, equal to the folder name, without the words
  anthropic and claude and not =synced=, and never a name claude.ai reserves
  (the adapted learn skill ships as =tutor=). The name says the job
  (=verifying-before-claiming-done=) or the domain (=qt-quick=).
- /Subagents/ : a role noun (=scout=, =gate-runner=, =reviewer=), equal to the
  file name.
- /Hooks/ : snake case Python scripts named for their job (=guard_bash.py=,
  =after_edit.py=, =session_refresh.py=, =compact_brief.py=); a hook that
  serves several tools takes =--tool <name>=.
- /Docs/ : root hubs in upper case (=README.org=, =DESIGN.org=), the rest in
  hyphen case under =docs/=.
- /Terms/ : one word per concept, as [[file:docs/glossary.org][docs/glossary.org]] names it.

* Rules that bind

These rules bind every change to this repository; a change that conflicts with
one stops and states the conflict. Where a skill or the global rules name the
project's decision log, this section is it. The maintainer decides: a rule
lands here, as the rule and its reason, only after the maintainer accepts it
or says "decide", and a changed rule is rewritten in place by the commit that
changes it, so git keeps its history. A proposed rule binds nobody until the
maintainer accepts it. Record a rule when reversing it
would cost real work, or when someone is likely to propose the rejected option
again.

Each rule has a stable anchor, its =CUSTOM_ID=, for skills and docs to cite
(for example =DESIGN.org#no-agent-push=; an Org link adds =::= before the
=#=), and an "In:" line naming the files that carry it out. A changed rule
keeps its anchor.

Each rule has a guide, the text that tells the agent to keep it, and a
sensor, the check that catches a breach. The reviewer checks every change
against all of them (conflicts with Accepted decisions, in
=home/.agents/agents/reviewer.md=), so the table names only the sensors
specific to each rule: "none: the model only" means that, apart from that
review, only the agent's own care keeps the rule. "Planned" marks a check that
is designed but not merged yet.

** Working method

*** Refute before you rely is the core method
:PROPERTIES:
:CUSTOM_ID: refute-first
:END:
Every agent tries to break each claim its work depends on with the cheapest
check that could fail, records what broke in the progress log and the
handoff, and drafts a rule change for each lesson a rule should have taught.
It sits in the always-loaded global rules because problems were caught by
external checks and independent agents, never by rereading.

In: =home/.agents/AGENTS.md= (Refute before you rely), =session-close= (the
lessons).

*** Stop only when a refuted claim changes the plan
:PROPERTIES:
:CUSTOM_ID: stop-on-plan-change
:END:
A refuted claim, or a difference between reality and memory or a document,
stops the work for a report only when it changes the plan, a requirement or a
decision; anything else is corrected and recorded. Routine work keeps going,
and the user still hears first about every change to what was approved.

In: =home/.agents/AGENTS.md= (Refute before you rely, Grounding).

*** Independent low-stakes questions may share a message
:PROPERTIES:
:CUSTOM_ID: grouped-questions
:END:
decide asks one question at a time, except that up to four independent,
low-stakes questions, each with its default, may share one message. Trivial
setup choices do not each deserve a round; dependent questions still go one
by one.

In: =home/.agents/skills/decide/SKILL.md=, =home/.agents/AGENTS.md=
(Decisions).

*** Implementation keeps a progress log
:PROPERTIES:
:CUSTOM_ID: progress-log
:END:
implement writes =.private/progress/<slug>.<ext>= as it works: the baseline
check on the base commit, each step with its commit and check, each gate run
with the commit it ran on, each decision with who took it, its reason and the
alternative, each attempt that failed, and each review finding's disposition;
an agent's decision stays pending until the user keeps or changes it. The user reviews every choice in
one place, and a later session resumes from facts.

In: =home/.agents/skills/implement/SKILL.md= (section 5),
=home/.agents/skills/session-close/SKILL.md=.

*** Tests are written by the implementer and attacked by the reviewer
:PROPERTIES:
:CUSTOM_ID: tests-attacked
:END:
The implementer sees each test fail for the right reason; the reviewer names a
wrong implementation that would still pass it. An expected value changes only
with cited evidence, and deleting, skipping or loosening a test needs the
user's approval, except the test of a behavior an approved spec removes.
Every test gets an independent attack with no extra agent per step.

In: =home/.agents/skills/implement/SKILL.md= (section 7),
=home/.agents/agents/reviewer.md=, =claude-ai/skills/trustworthy-tests/=.

*** Learning lives in the global rules
:PROPERTIES:
:CUSTOM_ID: learning-in-global-rules
:END:
The Learning section stays in the always-loaded global rules, at about 600
tokens per session, so no context lacks it; the tutor skill adds depth on
top.

In: =home/.agents/AGENTS.md= (Learning), =claude-ai/skills/tutor/=.

** Source and install

*** One source of truth in =~/.agents=, generated copies per tool
:PROPERTIES:
:CUSTOM_ID: one-source
:END:
Instructions, skills, subagents and hooks have one source (=home/.agents=,
installed as =~/.agents=); =install.py= links or generates each tool's files
from it, and nothing is edited in a tool's own folder. Five agents read
different file names and formats, and hand-kept copies drift. Revisit if the
tools converge on one standard location for instructions, skills and
subagents.

In: =install.py=, =home/.agents/=.

*** Skills load locally from this repository
:PROPERTIES:
:CUSTOM_ID: skills-load-locally
:END:
The installer gives every local agent every skill, the claude.ai set
included, and turns off Claude Code's synced copies; changes reach claude.ai
by uploading the built zip. One version is edited and tested locally, and
Claude Code would otherwise list both copies.

In: =install.py= (=skillOverrides=), =tools/build.py=.

** Skills

*** Skills are concise and complete
:PROPERTIES:
:CUSTOM_ID: concise-skills
:END:
A skill holds every step and rule a model would otherwise get wrong, each
stated once; adapting a third-party skill changes only what conflicts with
the maintainer's rules. Once a skill loads, every token competes with the
conversation, and vague guidance fails too.

In: =docs/skill-authoring.org=, =AGENTS.md= (Hard rules).

*** New skills come from real runs, checked against primary sources
:PROPERTIES:
:CUSTOM_ID: skills-from-real-runs
:END:
The sources refuted several case-study claims (an SVG =sourceSize= multiplied
by the pixel ratio counts it twice; a diff threshold of 40 let real shifts
through). The runs added five rules to the workflow skills: full gates on the
final commit, a generated file changed at its generator, tests on the current
build, a check script trusted only after it catches a planted case, and
slowness measured.

In: =docs/skill-authoring.org=; the five rules in =implement=,
=verifying-before-claiming-done= and =systematic-debugging=.

*** Scripts in skills stay light
:PROPERTIES:
:CUSTOM_ID: light-scripts

A script a skill runs uses the standard library plus at most one common
package, and its tests run in CI without that package, so the skill works
wherever it is installed.

** What the skills teach

*** Every application gets every clean-architecture layer
:PROPERTIES:
:CUSTOM_ID: clean-architecture-layers
:END:
Domain, use cases, infrastructure, presentation and a composition root, with
dependencies pointing inward and repository interfaces in the domain; a use
case returns its result, and one that would only forward a call is left out
only as a decision the project records. One structure in every project, as
Martin, Evans, Fowler and Cockburn describe it, at the cost of heavier small
apps.

In: =home/.agents/skills/clean-architecture/SKILL.md=.

*** UI threads never block; work moves through events
:PROPERTIES:
:CUSTOM_ID: ui-never-blocks
:END:
event-driven-ui moves file writes, I/O and heavy work to long-lived workers
whose results come back as events, and keeps one loop with asynchronous APIs
when every handler fits the frame budget. It matches Chromium's, Android's,
Apple's and Qt's threading guidance, and a separate skill loads when a UI
freezes.

In: =home/.agents/skills/event-driven-ui/SKILL.md=.

*** Diagrams use the nexenne palette in day and night
:PROPERTIES:
:CUSTOM_ID: diagram-palette
:END:
Every PlantUML diagram includes the skill's =palette.iuml= and no other
styling, the skill names neither the palette's origin nor any project, and
groups are packages, not stereotypes. One file serves both themes, and a
light fill without its text colour was unreadable in the dark preview.

In: =home/.agents/skills/plantuml-diagrams/=.

*** As-built docs are written for people and synced, not rewritten
:PROPERTIES:
:CUSTOM_ID: as-built-for-people
:END:
Three documents, each opening with its own vocabulary and the big picture,
under a word budget, with titled UML diagrams, lookup facts in an appendix,
bugs left to code-audit and readability enforced by checks that fail; a rerun
syncs from the recorded commit. Earlier generated docs were tedious through
density.

In: =home/.agents/skills/as-built-docs/=.

*** As-built docs show the UI with rendered, annotated pictures
:PROPERTIES:
:CUSTOM_ID: as-built-pictures
:END:
Pictures come only from the real app driven to each state, each with a recipe
and a numbered legend that a check matches against its markers; when the app
cannot run, the user is asked and nothing is sketched. A description of an
app includes what the user sees, and rendered pictures stay true to the code.

In: =home/.agents/skills/as-built-docs/=.

*** Code audits report only confirmed findings and ask about the rest
:PROPERTIES:
:CUSTOM_ID: confirmed-audit-findings
:END:
code-audit writes a local report of findings confirmed by a check that could
fail, each with severity, confidence, =file:line= and evidence, keeps every
doubt as a question for the user, and fixes nothing. False positives make
people ignore a report.

In: =home/.agents/skills/code-audit/SKILL.md=.

** Git and license

*** No agent pushes or publishes
:PROPERTIES:
:CUSTOM_ID: no-agent-push
:END:
No agent pushes or publishes, in any tool; the guard and the Claude Code
settings enforce it. Agents commit to local branches; the maintainer reviews
every change before it leaves the machine, and pushes.

In: =home/.agents/hooks/guard_bash.py=, =adapters/claude/settings.json= (deny),
=install.py= (Codex rules), =home/.agents/AGENTS.md= (Agentic work, Git).

*** Parallel and risky work is isolated in worktrees
:PROPERTIES:
:CUSTOM_ID: isolated-worktrees
:END:
Writing agents that run in parallel, and a complex or risky change, each work
in their own git worktree and branch outside the main checkout. A branch lands
on the maintainer's go by rebase and fast-forward, for a linear history, and
then its worktree and branch are removed. The main checkout and the target
branch move only when reviewed work lands, and nothing is left behind.

In: =home/.agents/AGENTS.md= (Agentic work),
=home/.agents/skills/isolated-work/SKILL.md=.

:PROPERTIES:
:CUSTOM_ID: no-ai-attribution
