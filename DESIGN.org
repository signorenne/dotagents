#+TITLE: dotagents design
#+SUBTITLE: how the pieces compose and install, and the rules that bind
#+OPTIONS: toc:2 num:nil ^:nil
#+STARTUP: showall

This file owns dotagents' design: the public surface, how the pieces compose,
the install model, the hooks' failure model, what each costly component
assumes about the model, naming, and the rules that bind every change.
[[file:VISION.org][VISION.org]] owns the direction. [[file:AGENTS.md][AGENTS.md]] owns where each
change goes, the hard rules and the review checklist.
[[file:CONTRIBUTING.org][CONTRIBUTING.org]] owns the workflow and the docs format.
[[file:docs/skill-authoring.org][docs/skill-authoring.org]] owns how a skill is written. [[file:METHOD.org][METHOD.org]]
owns the method a change follows. [[file:docs/architecture.org][docs/architecture.org]] draws the
structure, the install flow and a session's runtime view.

North star: change a rule once, run the installer, and every agent in every
tool, and every claude.ai chat, follows the new text.

* Public surface

The global rules say how to work, a skill says how to do one kind of work, a
subagent does one job in a fresh context, and a hook enforces what must not
depend on the model remembering it.

- /Global rules/ : =home/.agents/AGENTS.md=, at most 9,000 characters
  (=tools/validate.py=) because the Claude Code pack prints them from a
  session-start hook, whose output Claude Code caps at 10,000 characters, and
  the same text is pasted into claude.ai. They cover priorities, sufficiency,
  refute before you rely, decisions, output, learning and agentic work in the
  method's vocabulary, and they bind every skill and subagent. A personal
  layer may append lines to the installed copy.
- /Local skills/ : one folder per skill under =home/.agents/skills/=, with a
  =SKILL.md=, a =LICENSE.txt= and, only where a real run showed the need, a
  reference file, templates or a =scripts/= folder.
- /claude.ai skills/ : one folder per skill under =claude-ai/skills/=, with
  descriptions of at most 200 characters. A local skill also wanted on
  claude.ai gets an entry in =claude-ai/overrides.json= with its short
  description, never a copy; =tools/build.py= swaps that description into the
  zip.
- /Subagents/ : =scout=, =gate-runner= and =reviewer= in
  =home/.agents/agents/=, in Claude Code format (name, description, tools,
  model, and where set effort, maxTurns and color), the source of every other
  tool's copy.
- /Hooks/ : =guard_bash.py=, =after_edit.py=, =session_refresh.py=,
  =compact_brief.py=, =step_log.py=, =context_nudge.py=, =claim_check.py= and
  =repeated_failure.py= in =home/.agents/hooks/=,
  shared by every tool; the guard and the after-edit hook learn which tool
  called them from =--tool=. The plan-file hooks reach the build skill's
  =planfile.py= by path (=../skills/build/scripts=).
- /Plan scripts/ : =plan_state.py=, =check_step.py= and =floor_check.py= with
  their shared =planfile.py= in =home/.agents/skills/build/scripts/=, standard
  library only (METHOD.org, Checks).
- /Packs/ : =.claude-plugin/marketplace.json= and =packs/<pack>/=, written by
  =python3 tools/build.py --marketplace=: four Claude Code plugins (method,
  craft, docs, chat) whose folders hold only relative links into
  =home/.agents= and =claude-ai/skills=.
- /Claude Code adapter/ : =adapters/claude/settings.json=: read-only git and
  build commands allowed, =git push= denied (also as =git -C <dir> push=),
  =git reset --hard=, =git clean=, =git rebase=, =git update-ref=,
  =git merge=, =git branch -f= (or =--force=), =-M= and =-C= and a forced =git branch= delete (=-D= and
  each other spelling of =--delete --force=) (all but the first two also as
  =git -C <dir> ...=) and =rm -rf= asked first, =.env= files, =~/.ssh= and =~/.gnupg= unreadable, commit and PR attribution
  empty, and the hook entries. The maintainer's own allows (cmake, ctest,
  clang tools, =./build/*=, the knowledge vault) and plugin switches live in
  the personal layer, =personal/=.

* How they compose

** Who loads what

- The global rules load at the start of every session: by the import in
  =~/.claude/CLAUDE.md= in Claude Code, through links in Codex, Gemini CLI,
  Antigravity CLI and Copilot CLI, and by paste in Cursor and claude.ai.
- A skill's description is listed to the model (Claude Code drops the least
  used ones past a budget); its =SKILL.md= loads when a request matches the
  description or the user calls it by name. A reference file next to it loads
  only when the skill says to read it.
- A subagent starts in a fresh context with its own file as instructions and
  its tool list: =scout= read-only, =gate-runner= running commands it does not
  fix, =reviewer= never editing. In Claude Code they run on Sonnet, Haiku and
  Opus, and =gate-runner= starts without the user, project and local
  =CLAUDE.md= files (=omitClaudeMd=), with only its own body and the brief;
  the other tools' copies drop that field. Codex ignores the =sandbox_mode= of
  a custom agent file, so there =scout= inherits the session's sandbox and
  stays read-only only by its instructions.
- Hooks run outside the model, on tool events, and reach it only through what
  they print.

** Skills hand off to each other

The repository workflow follows [[file:METHOD.org][METHOD.org]]. =scoping-before-building= or
=architecture-doc= sizes the work; =design= turns work that needs several
plans into a design and its ordered plans, settling choices with =decide=;
=build= takes one change through its lane, from the plan file to the
triaged review, and proposes =isolated-work= for high risk; =close= brings
the plan files up to date at the end of a session; on the maintainer's go,
=isolated-work= lands the branch and removes its worktree.

Off the chain: =as-built-docs= sends bugs and anomalies to =code-audit=;
=code-audit= sends a finding the user wants fixed to =build=, starting
with a failing test; =decision-analysis= researches products and returns a
project's choice to =decide=; =systematic-debugging= comes before
=event-driven-ui= when a freeze is unexplained, and in a repository leaves the
failing test and the fix to =build=; =parallel-agents= runs each writer
through =isolated-work=, each with its own plan file; =build= and the
reviewer apply =trustworthy-tests= to every new or changed test;
=context-handoff= gives way to =close= inside a git repository.

** Skills delegate to subagents

- =design=, =project-setup=, =code-audit= and =architecture-doc= map the
  code with =scout= before planning; =build= calls it only when the area is
  unknown or wide. =as-built-docs= reads the code with read-only subagents
  in a lower tier (in Claude Code the general-purpose subagent on Sonnet at
  effort medium, elsewhere the tool's default general agent) and measures
  that tier's coverage and error rate on every run (METHOD.org, Delegation).
- =gates=, =build=, =project-setup=, =isolated-work=, =as-built-docs= and
  =notes-from-work= run long commands through =gate-runner=, which reports the
  commit it tested, so only verdicts and first errors reach the conversation;
  =build= and =isolated-work= also give it the folder and the commit to
  test, and =parallel-agents= gates each branch through =isolated-work=.
- =branch-review=, =build=, =mechanical-changes= and =notes-from-work=
  hand the finished change to =reviewer= (quick or full mode), which reports
  the HEAD it reviewed; =build= also gives it the folder, the commit it
  expects there and the plan file, and =parallel-agents= runs build's review
  on the merged result.
- =design=, =build= (full lane), =architecture-doc= and =as-built-docs= verify
  their documents with a subagent that did not write them, and =code-audit= has each finding attacked
  by one briefed only on the claim and the code: in Claude Code the
  general-purpose subagent told not to edit, elsewhere =reviewer=.
  =notes-from-work= has its claims attacked by one given the claims and their
  sources, which runs its own probes: the general-purpose subagent in Claude
  Code, the tool's default general agent elsewhere, told to write only in its
  own scratch folder.
- Where a tool has no subagents, the skill follows
  =~/.agents/agents/<name>.md= itself.

** Working notes

Skills keep their working notes in the git-ignored =.private/= folder of each
repository: plan files and their logs in =.private/plans/<slug>.<ext>= and
=<slug>.log=, designs in =.private/designs/<slug>.<ext>=, the deferred list
in =.private/deferred.<ext>=, handoffs (only for a session no plan file
holds) in =.private/handoff/<YYYY-MM-DD>-<slug>.<ext>=, audit reports in
=.private/audit/= and the notes of =as-built-docs= in =.private/as-built/=. A
worktree has no =.private/=, so work in one keeps its notes in the main
checkout's. A project's decisions go to its own decision log, never to working
notes.

* Install model

There is one source, =home/.agents=, installed as =~/.agents=
([[#one-source][one-source]]). =install.py= copies it there, adds the claude.ai set to
=~/.agents/skills/=, then links or generates each tool's files from it.
Nothing is edited in a tool's own folder: a change is made here and the
installer runs again. Each tool is a description in =TOOL_DESCRIPTIONS=
(its base folder, where its rules, skills, subagents and hooks go, its hook
format and timeout unit, extra steps, notes), and one engine installs them
all; =tests/test_install.py= (Descriptions) checks every description with
one suite.

| Agent           | Global rules                                                    | Skills                                                      | Subagents                                   | Hooks                                                                                                  |
|-----------------+-----------------------------------------------------------------+-------------------------------------------------------------+---------------------------------------------+--------------------------------------------------------------------------------------------------------|
| Claude Code     | =~/.claude/CLAUDE.md= imports =~/.agents/AGENTS.md=             | every skill linked in =~/.claude/skills=, synced copies off | =~/.claude/agents=                          | =~/.claude/settings.json=, with PostToolUseFailure, PreCompact, Stop, and SessionStart on every source |
| Codex           | =~/.codex/AGENTS.md= link                                       | reads =~/.agents/skills=                                    | =~/.codex/agents/*.toml=                    | =~/.codex/hooks.json=, with Stop and SessionStart (approve in Codex)                                   |
| Gemini CLI      | =~/.gemini/GEMINI.md= link; =context.fileName= adds =AGENTS.md= | reads =~/.agents/skills=                                    | =~/.gemini/agents/*.md=                     | =~/.gemini/settings.json=, with SessionStart on startup, resume, clear                                 |
| Antigravity CLI | =~/.gemini/GEMINI.md= link, shared with Gemini CLI              | =~/.gemini/config/skills.json= lists =~/.agents/skills=     | none                                        | =~/.gemini/config/hooks.json=                                                                          |
| Copilot CLI     | =~/.copilot/copilot-instructions.md= link                       | reads =~/.agents/skills=                                    | =~/.copilot/agents/*.agent.md=              | =~/.copilot/hooks/agents-global.json=, with sessionStart                                               |
| Cursor          | paste =~/.agents/AGENTS.md= into User Rules                     | reads =~/.agents/skills=                                    | reads =~/.claude/agents= (with Claude Code) | reads the Claude Code hooks (with Claude Code); =~/.cursor/hooks.json= with sessionStart               |

- /Generated, not copied by hand/ : each tool's subagent file is rendered from
  the Claude Code source (TOML for Codex, Markdown for Gemini CLI, =.agent.md=
  for Copilot CLI), with tool names mapped to the tool's own; the Codex copy
  carries the reasoning effort, and the Gemini CLI copy a turn and a time limit
  (=max_turns= from the source's =maxTurns=, =timeout_mins=) above Gemini
  CLI's defaults; Codex and Copilot CLI agents have no turn limit, so their
  copies carry none. A skill wanted on
  claude.ai is an override entry, never a second folder.
- /Checked before it starts/ : the installer validates the subagents and the
  JSON sources first and installs nothing when one is broken.
- /Backups/ : every file the installer replaces is moved to
  =~/.agents-backup/<timestamp>/= first; =--dry-run= prints every change and
  touches nothing.
- /Manifest/ : =~/.agents/.dotagents-manifest.json= records each file and
  link the installer wrote (its hash or target, and the tool or target it
  belongs to), each value it merged into a settings file, the folders it
  made, the personal layer and the targets. A later run replaces a recorded
  file only while it still holds what was installed; one changed by hand is
  kept with a note, and =--force= backs it up and replaces it. A recorded
  file that this version no longer installs is backed up and removed when
  unchanged. =--uninstall= removes every recorded file still as installed,
  the hook entries and the recorded values, the folders it made once empty,
  and the manifest; the files an install replaced stay in the backups.
- /Personal layer/ : =--personal DIR= (recorded; =--no-personal= stops it)
  appends =DIR/AGENTS.md= to the installed global rules and merges
  =DIR/claude-settings.json= into Claude Code's settings after the shared
  fragment (values only, no hooks); =personal/= is the maintainer's.
- /Generic target/ : =--target DIR[:RULES]= (recorded) links every skill into
  =DIR/skills= and the global rules into =DIR/RULES= (=AGENTS.md= by default),
  for a tool the installer does not describe yet; OpenCode, Goose, Qwen Code
  and Pi read =~/.agents/skills= themselves, Kimi only when
  =~/.config/agents/skills= does not exist. A =~/.claude/CLAUDE.md= without the import of
  =~/.agents/AGENTS.md= is replaced by one with it, and the old file is in the
  backup.
- /Idempotent/ : a file whose bytes already match is left alone, so a second
  run changes nothing.
- /Merged settings/ : the Claude Code adapter, Codex's and Gemini CLI's hook
  entries are merged into the tool's settings file: earlier copies of this
  repository's hook entries are removed and the current ones appended, a rule
  the adapter denies is removed from =ask= (where an older install put it),
  and the rest of the file is kept; one merge per file and run, so a value
  that cannot take ours leaves the whole file alone. Antigravity CLI's hooks
  file maps hook names to
  events: the installer rewrites its own two names (=dotagents-guard=,
  =dotagents-after-edit=), keeps an =enabled= value set by hand, and adds
  =~/.agents/skills= to the entries of the skills manifest. A file that does
  not parse is left alone with a note to merge it by hand.
- /Antigravity CLI/ : it replaced Gemini CLI for Google AI Pro, Ultra and free
  users on 18 June 2026; Gemini CLI stays for Code Assist licences and paid
  API keys, so both adapters stay. Antigravity CLI gets the guard and the
  after-edit hook but no session refresh, because it documents no event after
  a compaction or a resume, and no subagents yet. It is detected by
  =~/.gemini/antigravity-cli= or the =agy= command.
- /COPILOT_HOME/ : when it is set, Copilot CLI's files go to
  =$COPILOT_HOME= instead of =~/.copilot=, since it replaces that whole path;
  a relative value is refused with a note.
- /Path rules/ : =home/.agents/path-rules.json= maps a skill to the file
  globs that call for it (QML to qt-quick, PlantUML to plantuml-diagrams,
  tests to trustworthy-tests). For Claude Code the installer writes one
  =~/.claude/rules/dotagents-<skill>.md= per entry, whose =paths= make it
  load only with a matching file; it replaces only its own =dotagents-*.md=
  files (backed up first) and backs up those the source dropped. The other
  tools get none yet.
- /Codex rules/ : the installer writes =~/.codex/rules/dotagents.rules=, whose
  =prefix_rule= entries forbid the git commands that push or publish, every
  command of gh 2.100.0 but the read or local ones the guard lets through
  and =gh api=, and the token prints as far as a prefix can say them:
  =gh auth token= and =git-credential=, =gh auth status= with =-t=,
  =--show-token=, =-at=, =-ta=, =-t=true= or =--show-token=true= right after
  it, and =gh config get oauth_token= without =-h=. A prefix rule cannot
  forbid all but a list nor see past its words, so a =gh= command added
  later, a flag before the subcommand (=gh -R o/r pr create=) or before the
  token flag (=gh auth status -a -t=) are the guard's alone. Codex writes
  =default.rules= itself, and the installer leaves it alone.
- /skillOverrides/ : claude.ai syncs its copy of each uploaded skill into
  Claude Code as =anthropic-skills:<name>=, and Claude Code would list it next
  to the local one. The installer sets each of those to =off= in
  =~/.claude/settings.json=; a value set by hand wins.
- /Leftovers of versions without a manifest/ : the first install over one
  backs up a file dropped from a skill folder that still exists, the skills
  this repository renamed or dropped (=review=, =implement=, =spec=,
  =session-close=, when their =SKILL.md= has our name line and license) with
  their Claude Code links, the renamed hook script =progress_check.py=
  (whose settings entries the merge recognizes as ours), and the legacy items
  of older versions (their =learn= and =handoff= skill copies and the hook
  copies in =~/.claude/hooks=). =--audit= lists what in the agents' folders
  does not come from here, and broken links, and changes nothing.

Claude Code is tested end to end. The other tools' files follow their official
documentation, and =tests/test_install.py= checks each generated hook file
against it (events, matchers, tool names, timeouts).

* Hooks and their failure model

| Hook                  | Runs                                          | Tools                                                                                                    | Timeout |
|-----------------------+-----------------------------------------------+----------------------------------------------------------------------------------------------------------+---------|
| =guard_bash.py=       | before a shell command                        | all six (Cursor through Claude Code's)                                                                   | 10 s    |
| =after_edit.py=       | after a file edit or write                    | all six (Cursor through Claude Code's)                                                                   | 60 s    |
| =session_refresh.py=  | at session start: new, clear, compact, resume | Claude Code, Codex; JSON: Gemini CLI (start, resume, clear), Copilot CLI (start, resume), Cursor (start) | 10 s    |
| =compact_brief.py=    | before a compaction                           | Claude Code                                                                                              | 10 s    |
| =step_log.py=         | before the agent ends its turn                | Claude Code, Codex                                                                                       | 10 s    |
| =context_nudge.py=    | after a shell command                         | Claude Code                                                                                              | 10 s    |
| =claim_check.py=      | before the agent ends its turn                | Claude Code                                                                                              | 10 s    |
| =repeated_failure.py= | after a shell command fails                   | Claude Code                                                                                              | 10 s    |

The guard blocks git gate bypasses (=--no-verify=, =commit -n=, hook skip
variables, a disabled =core.hooksPath=) and every push and publish, in every
tool: =git push=, =git subtree push=, =git send-pack=, =git http-push=,
=git lfs push=, =git svn dcommit=, =git p4 submit=, =git send-email= and
every =gh= command but those that only read or work locally (=view=,
=list=, =diff=, =status= and =checks= in any group, =repo= and =gist clone=,
=pr checkout=, =run watch= and =download=, =release download=, =config= and
=variable get=, =repo read-file= and =read-dir=, =ruleset check=,
=attestation verify=, =search=, =status=, =browse=, =completion=,
=licenses=, =version= and help), so a write command =gh= adds later is
blocked too ([[#no-agent-push][no-agent-push]]). A flag other than =-R= or =--repo= before a
=gh= subcommand makes the command unknown, so it is blocked: =gh= takes the
flag's next word as its value while it looks for the subcommand. The guard
also blocks the =gh= commands that print the authentication token, which
would stay in the session's transcript: =gh auth token=,
=gh auth git-credential=, =gh auth status= with =-t= or =--show-token=
(anywhere, also in a cluster such as =-at=, the last value winning) and
=gh config get oauth_token=. It finds all of these also run through
=find -exec= (nested too), wrappers such as =sudo=, =watch=, =strace=,
=parallel=, =systemd-run= or =nsenter=, the remote command of =ssh=, or
git's own programs (=git-push=). A
push that also rewrites or deletes published history (=--force= and its
variants, =+refspec=, =--delete=, =:ref=, =--mirror=, =--prune=) and
=gh pr merge --admin= are named as such. The after-edit hook flags em and en
dashes in the text just written and runs clang-format, when the project has
a =.clang-format=, on the lines of a C or C++ file that the edit changed (a
newly written file whole), and checks the syntax of an edited Python, JSON
or TOML file with the standard library (TOML from Python 3.11, which
brought =tomllib=).
The session refresh prints, on a task branch whose plan file exists, the
build skill's plan excerpt (=plan_state.py --excerpt=: header, step in
progress, open rulings, last log lines, marked as a map, at most 4,000
characters for Codex's cap of about 2,500 tokens); on a new session or a
clear that is all, and nothing without a plan. After a compaction or a
resume it first reminds the agent that its picture of the code is a summary
(after a compaction, also to invoke its workflow skill again, since Claude
Code keeps only the start of each skill through one) and prints the real
branch, changes, last commits and other worktrees; without a plan excerpt
it lists the newest plan files and handoffs (in a linked worktree, the main
checkout's). The compaction brief tells the summary what resuming needs:
the task and its slug, the branch, the plan file's path, the workflow skill
and its running section or step, the current plan step, the rulings still
pending and the user's choices, the user's constraints that no file records
(word for word) and what is blocked on what, the files changed and the
commands still needed with their last results; it fills in the branch, the
uncommitted changes and the plan file (or the newest notes) itself. The step
log runs when the agent ends its turn: on a branch =<type>/<slug>= whose plan
file exists, it appends to =<slug>.log= a commit line for each commit of the
branch (one no other local or remote-tracking branch holds) that the log
does not name yet, prints nothing and never keeps the agent going. The
context nudge runs after a shell command that made a commit, in Claude Code:
on a task branch with a plan file, when the last request's context passed
200,000 tokens, it shows the user (=systemMessage=) that this is a good point
to clear the session. The claim check runs at the same moment, in Claude Code
only: when the agent's final message says the tests pass ("all tests pass",
"189 tests OK", "the suite is green", but not a hedged "should pass"), it
reads the end of the session's transcript and sends the agent back once, to
run the tests or say they were not run after its last edit, when after the
last file edit nothing but commands that certainly run no tests came,
whether or not a test ran before that edit, or when the last known run
failed and no command of unknown kind followed it. It sorts each shell
command, split with the guard's shell parser, into three kinds (the
maintainer's rule): a known test run (a test runner, or a script or build
target named test, gate, check or verify, also behind wrappers, launchers
and =bash -c=), judged by its runner's summary lines and, when none
matches, by the call's exit status; a quiet command (=git status=, =add=,
=commit=, =diff=, =log=, =show=, =restore= or =stash=, =cat=, =ls=, =grep=,
=find=, =sed -n= and the like), which counts as a run only when its output
shows a runner's summary, as =git commit= running the tests in its hooks
does; and anything else, which may have run tests, so its outcome is
unknown. A quiet or unknown command whose result records changed files
counts as an edit (a known test run's changed files do not), and an unknown
one then also as a run of unknown outcome; PowerShell commands are read
like Bash ones; a subagent or an MCP tool counts as a run of unknown
outcome too. Edits of task notes (=.private/=), temporary files, the
scratchpad and =~/.claude= do not count. The repeated
failure hook counts each failing shell command per session, by its command
and its whole error with each word that holds a digit masked after the first
line (timings, counts, addresses and temporary names change between runs);
from the third identical failure on
it reminds the agent to stop after two failed fixes, restate its
assumptions and evidence, change approach (=systematic-debugging=) and, if
that fails too, report to the user.

The hooks share one failure model:

- /Never block on unreadable input/ : a payload that does not parse exits 0,
  so a broken payload never stops normal work. The session refresh never fails
  the session.
- /A guard that cannot run blocks in Claude Code/ : its entry sets
  =onFailure= to =block= (Claude Code v2.1.295 or later), so a guard that
  cannot start, crashes, times out or prints invalid output blocks the
  command as exit 2 would; a broken install never lets a push through. A
  payload it cannot read is not a failure: it still exits 0.
- /Never block a compaction/ : exit 2 from a PreCompact hook blocks the
  compaction, and one that recovers from a full context then fails the
  request. The compaction brief always exits 0, and its command ends in
  =|| true= because =python3= itself exits 2 when the script is missing.
- /Send the agent back at most once/ : exit 2 or a block decision from a Stop
  hook keeps the agent going, Codex documents no cap on it, and Cursor runs
  Claude Code's Stop hooks with no cap and without =stop_hook_active=. The
  claim check blocks only when =stop_hook_active= is =false=; it and the step
  log (which never blocks) let every error through, and their commands end in
  =|| true=.
- /Block with exit 2/ : the reason goes to stderr, which the agent sees.
  Copilot CLI shows stderr only to the user, so the guard also prints a deny
  decision with the reason on stdout, and the after-edit hook sends its report
  as model context with exit 0. Antigravity CLI documents a JSON reply and no
  exit codes, so there the guard answers a deny decision with the reason and
  exit 0; its after-edit reply is ={}=, which carries nothing to the agent, so
  there the hook formats and exits 0, and its dash report goes only to stderr.
- /JSON only on Gemini CLI's and Antigravity CLI's stdout/ : both read a
  hook's stdout as JSON, so nothing else is printed there. Notices reach the
  model as additional context in each tool's documented format.
- /Finish inside the timeout/ : Claude Code drops all output of a hook that
  times out, so each hook bounds its own work below the configured timeout
  (8 s for the plan excerpt, the notes listing and the git calls of the
  session refresh and of the compaction brief, 1 to 1.5 s per git call of
  the plan-file hooks, clang-format under 60 s,
  the last 4,000,000 bytes of the transcript for the claim check, a regular
  file opened without blocking); the brief also stays under the 10,000
  characters past which Claude Code cuts it.
- /Two locks on a push/ : the guard blocks pushes and publishes in every tool,
  and in Claude Code the adapter also denies =git push=, so the permission
  prompt never offers it. In Codex, =~/.codex/rules/dotagents.rules= forbids
  the same git commands, the =gh= commands that are not read or local and
  the plain forms of the token prints, and holds even while Codex skips
  hooks the user has not trusted yet; Codex
  calls its rules experimental, and a prefix rule cannot see
  =git -C <dir> push=, which the guard catches.
- /Not a security boundary/ : the guard splits the command as a shell does and
  falls back to a rough split when it does not parse, so a parse error never
  lets a forbidden command through; commands passed as one string (=bash -c=,
  =env -S=, =flock -c=, =git submodule foreach=, the arguments after
  =parallel='s =:::=), =eval=, aliases, scripts and =gh api= are not
  inspected, nor programs it does not know that run their arguments (such as
  =numactl= or =faketime=). It reads the remote command of =ssh= as shell
  text, but not one given as =-o RemoteCommand=, nor the command of =autossh=
  or =mosh=.
  =tests/test_hooks.py= holds a battery of the forms it does catch.

* What each costly component assumes

Each component below costs tokens, time or a session, and each rests on an
assumption about what the model cannot do on its own. Anthropic's
[[https://www.anthropic.com/engineering/harness-design-long-running-apps][Harness design for long-running apps]]
(24 March 2026, a vendor engineering report) says every such component encodes
an assumption worth stress testing, because it may be wrong and can go stale
as models improve: its author dropped context resets once Opus 4.5 largely
stopped showing the behavior they countered and the sprint structure once Opus
4.6 could do the work without that decomposition, but kept the planner and the
evaluator, which still added clear value (here design, the full lane's plan check and the reviewer play
those parts). Re-examine this list when a new model becomes the default for a
role, and change or retire a component when the observation named for it
holds; the plan files and their logs hold most of the evidence (each review
finding with its verdict, each gate run with its result). This section records reasons,
not rules: a change that touches a rule that binds still follows that rule.

- /Plan and design verification/ (design step 5 and build's full lane: a
  subagent that did not write the document paraphrases it, then checks every
  claim and gives a second reading of each criterion) : assumes the writer
  misses its own errors (a wrong path or symbol, an unverifiable claim, a
  criterion with two readings) and that a reader who has only the document
  finds where it is ambiguous. Revisit when, over several plans, it finds
  nothing the writer had not already caught.
- /Reviewer/ (in Claude Code Opus at high effort, in a fresh context) :
  assumes the writer misses its own errors and the weak spots of its own
  tests, and that the strongest model, free of the writing context, finds
  them. Revisit when its findings on several branches are all minor or
  already caught by the gates: a cheaper model or effort, or a review only
  of changes across modules, would then do.
- /The reviewer's second pass/ (only at high risk, when a fix added a public
  surface or the maintainer pinned a thorough review: =single-review-pass=) :
  assumes a fix made under review brings errors of its own; elsewhere each
  behavior-changing fix is proven by a test seen failing first instead. The
  baseline found later-pass majors in 6 of about 21 changes; fail rule R
  watches whether dropping the pass costs quality.
- /scout/ (in Claude Code Sonnet) : assumes reading a whole area fills the
  main context and degrades the plan, and that a cheaper model maps it
  reliably into a short cited brief. build calls it only for an unknown or
  wide area, and reuses a code map whose paths have not changed since it was
  checked. Revisit
  when plans made without it are no worse, or when its briefs miss owners or
  callers the plan then needs.
- /gate-runner on a cheaper model/ (in Claude Code Haiku at low effort,
  without the =CLAUDE.md= files) : assumes a cheaper model is enough to run
  documented commands and report the verdicts and the first errors, and that
  long logs cost the main context more than a subagent call. Revisit when it
  reports a wrong verdict or misses a first error (raise its model or
  effort), or when the main model can read gate output as cheaply.
- /Session refresh and compaction brief/ : assume a compaction summary loses
  the task's state (the branch, the plan step, the pending rulings, the
  user's unrecorded constraints) and that the model then trusts its summary
  as the current code; Claude Code also keeps only the first 5,000 tokens of
  each skill invoked before a compaction. Revisit when real sessions show the
  summary keeps that state without the brief (unmeasured today), or
  when the tool keeps whole skills through a compaction.
- /A fresh session between the plans of a design/ : assumes the design
  conversation (the interview, the rejected options) would steer the
  build, and that only a reader without it shows the design and the plan are
  self-contained. Revisit when builds run in the design's own session match
  their plans as well, by the reviewer's findings, over several tasks.
- /maxTurns caps/ (250 for scout and reviewer, 200 for gate-runner) : assume
  a subagent can loop without converging, so a cap bounds its cost; they sit
  above the longest of about 490 past runs ([[file:docs/architecture.org][docs/architecture.org]]).
  Revisit when a legitimate run reaches its cap (raise it), and count the
  runs again when a new model changes how long they take.

** Working method

*** Refute before you rely is the core method
:PROPERTIES:
:CUSTOM_ID: refute-first
:END:
Every agent tries to break each claim its work depends on with the cheapest
check that could fail, records what broke in the plan file (or, with no
plan, the handoff), and drafts, for each lesson a rule should have taught, a
check that catches the mistake when one command or tool call can, otherwise
a rule change.
It sits in the always-loaded global rules because problems were caught by
external checks and independent agents, never by rereading.

In: =home/.agents/AGENTS.md= (Refute before you rely), =close= (the
lessons).

*** The work stops only for a closed list; every other choice is a ruling
:PROPERTIES:
:CUSTOM_ID: closed-stop-list
:END:
During a change the agent stops only for a change to the frozen intent; a
public API, architecture, dependency, data migration or other choice that
is the maintainer's the plan does not hold; an irreversible, destructive or
security-sensitive action; a test or gate that could pass only by being
deleted or loosened; a conflict with an accepted decision; two changed
approaches that both failed; a plan so broken that every path is a guess.
Every other choice is a ruling, recorded in the plan with its reason, the
alternative and what it costs if wrong, and listed at the end for the
maintainer's review. In 13 days the agent stopped for 375 question rounds
against 477 prompts. Replaces =stop-on-plan-change=.

In: =METHOD.org= (Questions and stops), =home/.agents/AGENTS.md=
(Agentic work), =home/.agents/skills/build/SKILL.md=.

*** Questions come in one batch, after an assumptions table
:PROPERTIES:
:CUSTOM_ID: one-batch
:END:
Before approval the agent shows, in one message, its assumptions as a table
(evidence, what breaks if wrong, how sure) and the open questions that are
the maintainer's, each with options, consequences and its recommendation.
One answer approves the plan. decide does the same: the assumptions table
first, then independent questions together, a dependent one after the
answer it depends on. Replaces =grouped-questions=.

In: =METHOD.org=, =home/.agents/skills/build/SKILL.md=,
=home/.agents/skills/decide/SKILL.md=, =home/.agents/AGENTS.md= (Decisions).

*** One plan file per change carries its state
:PROPERTIES:
:CUSTOM_ID: plan-file
:END:
A quick or full change keeps one plan file, =.private/plans/<slug>.<ext>=: a
state header the scripts read, the intent frozen at approval, the code map,
assumptions, steps, rulings, dead ends and review; the log beside it,
written only by scripts and hooks, records each check, failing-first run,
gate and commit. Any session resumes from it, and no handoff is written
where a plan exists. Replaces =progress-log=.

In: =METHOD.org= (The plan file), =home/.agents/skills/build/=, =close=,
=home/.agents/hooks/step_log.py=, =home/.agents/hooks/session_refresh.py=.

*** Tests are written by the implementer and attacked by the reviewer
:PROPERTIES:
:CUSTOM_ID: tests-attacked
:END:
The implementer sees each test fail for the right reason, and check_step
records the failing run; the reviewer names a wrong implementation that
would still pass each new or changed test. A test a review fix adds is
proven by a failing run and attacked again only when the risk is high or
the fix added a public surface; a change the maintainer pinned to no review
has no reviewer attack, only its failing runs. An expected value changes only with cited
evidence, and deleting, skipping or loosening a test needs the maintainer's
approval, except the test of a behavior an approved plan removes.

In: =home/.agents/skills/build/SKILL.md= (sections 5 and 7),
=home/.agents/agents/reviewer.md=, =claude-ai/skills/trustworthy-tests/=.

*** Every change takes a lane
:PROPERTIES:
:CUSTOM_ID: lanes
:END:
Every change in a repository takes a lane, said after investigating so the
maintainer can override it in one word: direct (one sentence, one or two
known files), quick (about 100 changed lines or fewer, no risk surface, no
choice of the maintainer's: announced and not awaited, one quick review)
or full (anything larger or any risk surface: one approval holding every
question, the full review). A lane goes up, never down; floor_check raises
a quick change that outgrew its lane. Revisit by fail rule Q.

In: =METHOD.org= (Lanes), =home/.agents/AGENTS.md= (Agentic work),
=home/.agents/skills/build/SKILL.md=, =floor_check.py=.

*** build, design and close are the entries
:PROPERTIES:
:CUSTOM_ID: one-entry
:END:
build plans and builds one change; design exists only for work that needs
several plans; close ends a session. They replace spec, implement and
session-close.

In: =home/.agents/skills/build/=, =design/=, =close/=.

*** One review pass unless the risk is high
:PROPERTIES:
:CUSTOM_ID: single-review-pass
:END:
A second reviewer pass, limited to the fixes, happens only when the risk is
high, a fix added a public surface or the maintainer pinned a thorough
review for the change; every behavior-changing fix is proven by a test seen
failing first. The maintainer can also pin no review for a change. Revisit
by fail rule R.

In: =METHOD.org= (Review and triage), =home/.agents/skills/build/SKILL.md=
(section 7).

*** Implementation runs in the main conversation
:PROPERTIES:
:CUSTOM_ID: inline-build
:END:
Handing a whole plan to one builder subagent is an experiment, adopted only
when the numbers show shorter sessions at equal quality.

In: =METHOD.org= (Resume and short contexts).

*** Every delegation names its form, size, model and effort
:PROPERTIES:
:CUSTOM_ID: delegation-tiers
:END:
Every delegation names its return form, a size limit, the model and the
effort; judgment (review, fact-checks, verdicts) stays on the strongest
model; the session's own effort stays the maintainer's setting.

In: =METHOD.org= (Delegation), =home/.agents/AGENTS.md= (Agentic work), the
fan-out skills.

*** A terse register, full sentences where someone acts
:PROPERTIES:
:CUSTOM_ID: terse-register
:END:
Chat replies and status lines use the terse register (answer first, no
ceremony, every fact kept, at most one short line between tool calls), and

In: =METHOD.org= (Register), =home/.agents/AGENTS.md= (Output).

*** METHOD.org owns the method
:PROPERTIES:
:CUSTOM_ID: method-owner
:END:
The global rules state the method's core in its vocabulary and the skills

In: =METHOD.org=.

** What the skills teach

*** Every application gets every clean-architecture layer
:PROPERTIES:
:CUSTOM_ID: clean-architecture-layers
:END:
Domain, use cases, infrastructure, presentation and a composition root, with
dependencies pointing inward and repository interfaces in the domain; a use
case returns its result, and one that would only forward a call is left out
only as a decision the project records. One structure in every project, as
Martin, Evans, Fowler and Cockburn describe it, at the cost of heavier small

*** UI threads never block; work moves through events
:PROPERTIES:
:CUSTOM_ID: ui-never-blocks
:END:
event-driven-ui moves file writes, I/O and heavy work to long-lived workers
whose results come back as events, and keeps one loop with asynchronous APIs
when every handler fits the frame budget. It matches Chromium's, Android's,
Apple's and Qt's threading guidance, and a separate skill loads when a UI
freezes.

** Git and license

*** No agent pushes or publishes
:PROPERTIES:
:CUSTOM_ID: no-agent-push
:END:
No agent pushes or publishes, in any tool; the guard and the Claude Code
settings enforce it. Agents commit to local branches; the maintainer reviews
every change before it leaves the machine, and pushes.

*** Commits may go straight on main in this repository
:PROPERTIES:
:CUSTOM_ID: main-commits-here
:END:
In dotagents, small commits may go straight on the local main branch, an
exception to the global rule "work on a branch, never on main": nothing
leaves the machine until the maintainer has reviewed it and pushed it.
Parallel or risky work still runs in its own worktree and lands by rebase and
fast-forward ([[#isolated-worktrees][isolated worktrees]]).

In: =AGENTS.md= (Hard rules).

*** Parallel and risky work is isolated in worktrees
:PROPERTIES:
:CUSTOM_ID: isolated-worktrees
:END:
Writing agents that run in parallel, and a complex or risky change, each work
in their own git worktree and branch outside the main checkout. A branch lands
on the maintainer's go by rebase and fast-forward, for a linear history, and
then its worktree and branch are removed. The main checkout and the target
branch move only when reviewed work lands, and nothing is left behind.
