#+TITLE: dotagents design
#+SUBTITLE: how the pieces compose and install, and the rules that bind
#+OPTIONS: toc:2 num:nil ^:nil
#+STARTUP: showall

This file owns dotagents' design: the public surface, how the pieces compose,
the install model, the hooks' failure model, naming, and the rules that bind
every change. [[file:VISION.org][VISION.org]] owns the direction. [[file:AGENTS.md][AGENTS.md]] owns where each
change goes and the review checklist. [[file:docs/skill-authoring.org][docs/skill-authoring.org]] owns how a
skill is written. [[file:docs/architecture.org][docs/architecture.org]] draws the structure, the install flow
and a session's runtime view.

North star: change a rule once, run the installer, and every agent in every
tool, and every claude.ai chat, follows the new text.

* Public surface

The global rules say how to work, a skill says how to do one kind of work, a
subagent does one job in a fresh context, and a hook enforces what must not
depend on the model remembering it.

- /Global rules/ : =home/.agents/AGENTS.md=, kept under 200 lines because the
  same text is pasted into claude.ai. They cover priorities, sufficiency,
  evidence, refute before you rely, grounding, decisions, output, learning and
  agentic work, and they bind every skill and subagent.
- /Local skills/ : one folder per skill under =home/.agents/skills/=, with a
  =SKILL.md=, a =LICENSE.txt= and, only where a real run showed the need, a
  reference file, templates or a =scripts/= folder.
- /claude.ai skills/ : one folder per skill under =claude-ai/skills/=, with
  descriptions of at most 200 characters. A local skill also wanted on
  claude.ai gets an entry in =claude-ai/overrides.json= with its short
  description, never a copy; =tools/build.py= swaps that description into the
  zip.
- /Subagents/ : =scout=, =gate-runner= and =reviewer= in
  =home/.agents/agents/=, in Claude Code format (name, description, tools,
  model), the source of every other tool's copy.
- /Hooks/ : =guard_bash.py=, =after_edit.py= and =session_refresh.py= in
  =home/.agents/hooks/=, shared by every tool; the guard and the after-edit
  hook learn which tool called them from =--tool=.
- /Claude Code adapter/ : =adapters/claude/settings.json=: read-only git and
  build commands allowed, =git push=, =git reset --hard=, =git clean=,
  =git rebase= and =rm -rf= asked first, =.env= files, =~/.ssh= and =~/.gnupg=
  unreadable, commit and PR attribution empty, and the hook entries.

* How they compose

** Who loads what

- The global rules load at the start of every session: by the import in
  =~/.claude/CLAUDE.md= in Claude Code, through links in Codex, Gemini CLI and
  Copilot CLI, and by paste in Cursor and claude.ai.
- A skill's description is listed to the model (Claude Code drops the least
  used ones past a budget); its =SKILL.md= loads when a request matches the
  description or the user calls it by name. A reference file next to it loads
  only when the skill says to read it.
- A subagent starts in a fresh context with its own file as instructions and
  its tool list: =scout= read-only, =gate-runner= running commands it does not
  fix, =reviewer= never editing. In Claude Code they run on Sonnet, Haiku and
  Opus; Codex runs =scout= in a read-only sandbox.
- Hooks run outside the model, on tool events, and reach it only through what
  they print.

** Skills hand off to each other

The repository workflow is a chain. =scoping-before-building= or
=architecture-doc= sizes the work; =spec= writes a self-contained plan and
settles each open choice with =decide=; a fresh session runs =implement= on
the spec; =implement= ends with the full gates and an independent review;
=session-close= records the state for the next session.

Off the chain: =as-built-docs= sends bugs and anomalies to =code-audit=;
=code-audit= sends a finding the user wants fixed to =implement=, starting
with a failing test; =decision-analysis= researches products and returns a
project's choice to =decide=; =systematic-debugging= comes before
=event-driven-ui= when a freeze is unexplained; =implement= and the reviewer
apply =trustworthy-tests= to every new or changed test; =context-handoff=
gives way to =session-close= inside a git repository.

** Skills delegate to subagents

- =spec=, =implement=, =project-setup=, =code-audit= and =architecture-doc= map
  the code with =scout= before planning; =as-built-docs= reads it with
  read-only subagents on the session's model (in Claude Code the
  general-purpose subagent, elsewhere =scout=).
- =gates=, =implement=, =project-setup= and =parallel-agents= run long commands
  through =gate-runner=, so only verdicts and first errors reach the
  conversation.
- =review= and =implement= hand the finished change to =reviewer=.
- =spec=, =architecture-doc= and =as-built-docs= verify their documents with a
  subagent that did not write them: in Claude Code the general-purpose
  subagent told not to edit, elsewhere =reviewer=.
- Where a tool has no subagents, the skill follows
  =~/.agents/agents/<name>.md= itself.

** Working notes

Skills keep their working notes in the git-ignored =.private/= folder of each
repository: specs in =.private/specs/=, progress logs in =.private/progress/=,
handoffs in =.private/handoff/=, audit reports in =.private/audit/= and the
notes of =as-built-docs= in =.private/as-built/=. A project's decisions go to
its own decision log, never to working notes.

* Install model

There is one source, =home/.agents=, installed as =~/.agents=. =install.py=
copies it there, adds the claude.ai set to =~/.agents/skills/=, then links or
generates each tool's files from it. Nothing is edited in a tool's own
folder: a change is made here and the installer runs again.

| Agent       | Global rules                                                    | Skills                                                      | Subagents                                   | Hooks                                                                |
|-------------+-----------------------------------------------------------------+-------------------------------------------------------------+---------------------------------------------+----------------------------------------------------------------------|
| Claude Code | =~/.claude/CLAUDE.md= imports =~/.agents/AGENTS.md=             | every skill linked in =~/.claude/skills=, synced copies off | =~/.claude/agents=                          | =~/.claude/settings.json=, plus SessionStart after compact or resume |
| Codex       | =~/.codex/AGENTS.md= link                                       | reads =~/.agents/skills=                                    | =~/.codex/agents/*.toml=                    | =~/.codex/hooks.json= (approve in Codex)                             |
| Gemini CLI  | =~/.gemini/GEMINI.md= link; =context.fileName= adds =AGENTS.md= | reads =~/.agents/skills=                                    | =~/.gemini/agents/*.md=                     | =~/.gemini/settings.json=                                            |
| Copilot CLI | =~/.copilot/copilot-instructions.md= link                       | reads =~/.agents/skills=                                    | =~/.copilot/agents/*.agent.md=              | =~/.copilot/hooks/agents-global.json=                                |
| Cursor      | paste =~/.agents/AGENTS.md= into User Rules                     | reads =~/.agents/skills=                                    | reads =~/.claude/agents= (with Claude Code) | reads the Claude Code hooks (with Claude Code)                       |

- /Generated, not copied by hand/ : each tool's subagent file is rendered from
  the Claude Code source (TOML for Codex, Markdown for Gemini CLI, =.agent.md=
  for Copilot CLI), with tool names mapped to the tool's own, and a skill
  wanted on claude.ai is an override entry, never a second folder.
- /Checked before it starts/ : the installer validates the subagents and the
  JSON sources first and installs nothing when one is broken.
- /Backups/ : every file the installer replaces is moved to
  =~/.agents-backup/<timestamp>/= first; =--dry-run= prints every change and
  touches nothing.
- /Idempotent/ : a file whose bytes already match is left alone, so a second
  run changes nothing.
- /Merged settings/ : the Claude Code adapter, Codex's and Gemini CLI's hook
  entries are merged into the tool's settings file: earlier copies of this
  repository's hook entries are removed and the current ones appended, and the
  rest of the file is kept. A file that does not parse is left alone with a
  note to merge it by hand.
- /skillOverrides/ : claude.ai syncs its copy of each uploaded skill into
  Claude Code as =anthropic-skills:<name>=, and Claude Code would list it next
  to the local one. The installer sets each of those to =off= in
  =~/.claude/settings.json=; a value set by hand wins.
- /Leftovers/ : the installer never removes what the repository dropped.
  =--audit= lists what in the agents' folders does not come from here, and
  broken links, and changes nothing.

Claude Code is tested end to end. The other tools' files follow their official
documentation, and =tests/test_install.py= checks each generated hook file
against it (events, matchers, tool names, timeouts).

* Hooks and their failure model

| Hook                 | Runs                                            | Tools                                   | Timeout |
|----------------------+-------------------------------------------------+-----------------------------------------+---------|
| =guard_bash.py=      | before a shell command                          | all five (Cursor through Claude Code's) | 10 s    |
| =after_edit.py=      | after a file edit or write                      | all five (Cursor through Claude Code's) | 60 s    |
| =session_refresh.py= | at session start after a compaction or a resume | Claude Code                             | 10 s    |

The guard blocks git gate bypasses (=--no-verify=, =commit -n=, hook skip
variables, a disabled =core.hooksPath=), pushes that rewrite or delete
published history (=--force= and its variants, =+refspec=, =--delete=,
=:ref=, =--mirror=, =--prune=), =gh pr merge --admin=, and every push outside
Claude Code. The after-edit hook flags em and en dashes in the text just
written and runs clang-format on C and C++ files when the project has a
=.clang-format=. The session refresh reminds the agent that its picture of the
code is a summary and prints the real branch, changes and last commits.

The hooks share one failure model:

- /Never block on unreadable input/ : a payload that does not parse exits 0,
  so a broken payload never stops normal work. The session refresh never fails
  the session.
- /Block with exit 2/ : the reason goes to stderr, which the agent sees.
  Copilot CLI shows stderr only to the user, so the guard also prints a deny
  decision with the reason on stdout, and the after-edit hook sends its report
  as model context with exit 0.
- /JSON only on Gemini CLI's stdout/ : Gemini CLI needs JSON on stdout when a
  hook succeeds, so nothing else is printed there. Notices reach the model as
  additional context in each tool's documented format.
- /Finish inside the timeout/ : Claude Code drops all output of a hook that
  times out, so each hook bounds its own work below the configured timeout
  (8 s of git calls in the session refresh, clang-format under 60 s).
- /The push rule/ : force pushes and deletions are blocked in every tool. A
  plain push is blocked outside Claude Code, Cursor included (recognised by
  =CURSOR_VERSION= or the =cursor_version= payload field); in Claude Code the
  adapter asks before every =git push=.
- /Not a security boundary/ : the guard splits the command as a shell does and
  falls back to a rough split when it does not parse, so a parse error never
  lets a forbidden command through; commands passed as one string (=bash -c=,
  =env -S=, =flock -c=, =git submodule foreach=), =eval=, aliases and scripts
  are not inspected.

* Documentation and skill design

Skills follow [[file:docs/skill-authoring.org][docs/skill-authoring.org]]: concise and complete, a description
that says what and when, one default instead of a menu, progressive
disclosure, and a test in a real session. The mechanical rules are in
[[file:AGENTS.md][AGENTS.md]] under Hard rules and =tools/validate.py= enforces them: only the
fields name, description and license; the name equal to the folder; a
description of at most 1024 characters (200 for the claude.ai set and the
overrides); a =LICENSE.txt= in every skill folder; no inline backticks in
skill prose; no em or en dash in any tracked file; the global rules under 200
lines.

Prose docs are Org. Markdown stays where a tool reads the file: =AGENTS.md=,
the bridges, the global rules, every skill file, and =claude-ai/README.md=,
which =tools/build.py= ships in the claude.ai bundle. Every doc opens with
what it owns and is registered in [[file:docs/README.org][docs/README.org]].

* Naming

- /Skills/ : lowercase kebab case, equal to the folder name, without the words
  anthropic and claude and not =synced=, and never a name claude.ai reserves
  (the adapted learn skill ships as =tutor=). The name says the job
  (=verifying-before-claiming-done=) or the domain (=qt-quick=).
- /Subagents/ : a role noun (=scout=, =gate-runner=, =reviewer=), equal to the
  file name.
- /Hooks/ : snake case Python scripts named for their job (=guard_bash.py=,
  =after_edit.py=, =session_refresh.py=); a hook that serves several tools
  takes =--tool <name>=.
- /Docs/ : root hubs in upper case (=README.org=, =DESIGN.org=), the rest in
  hyphen case under =docs/=.
- /Terms/ : one word per concept, as [[file:docs/glossary.org][docs/glossary.org]] names it.

* Rules that bind

These rules bind every change to this repository; a change that conflicts with
one stops and states the conflict. Where a skill or the global rules name the
project's decision log, this section is it. The maintainer decides: a rule
lands here, as the rule and its reason, only after the maintainer accepts it
or says "decide", and a changed rule is rewritten in place by the commit that
changes it, so git keeps its history. A proposed rule binds nobody and waits
under Proposed rules in [[file:docs/roadmap.org][docs/roadmap.org]]. Record a rule when reversing it
would cost real work, or when someone is likely to propose the rejected option
again.

** Working method

- /Refute before you rely is the core method./ Every agent tries to break each
  claim its work depends on with the cheapest check that could fail, records
  what broke in the progress log and the handoff, and drafts a rule change for
  each lesson a rule should have taught. It sits in the always-loaded global
  rules because problems were caught by external checks and independent
  agents, never by rereading.
- /Stop only when a refuted claim changes the plan./ A refuted claim, or a
  difference between reality and memory or a document, stops the work for a
  report only when it changes the plan, a requirement or a decision; anything
  else is corrected and recorded. Routine work keeps going, and the user still
  hears first about every change to what was approved.
- /Independent low-stakes questions may share a message./ decide asks one
  question at a time, except that up to four independent, low-stakes
  questions, each with its default, may share one message. Trivial setup
  choices do not each deserve a round; dependent questions still go one by one.
- /Implementation keeps a progress log./ implement writes
  =.private/progress/<slug>= as it works: each step with its commit and check,
  each decision with who took it, its reason and the alternative; an agent's
  decision stays pending until the user keeps or changes it. The user reviews
  every choice in one place, and a later session resumes from facts.
- /Tests are written by the implementer and attacked by the reviewer./ The
  implementer sees each test fail for the right reason; the reviewer names a
  wrong implementation that would still pass it. An expected value changes only
  with cited evidence, and deleting, skipping or loosening a test needs the
  user's approval, except the test of a behavior an approved spec removes.
  Every test gets an independent attack with no extra agent per step.
- /Learning lives in the global rules./ The Learning section stays in the
  always-loaded global rules, at about 600 tokens per session, so no context
  lacks it; the tutor skill adds depth on top.

** Skills

- /Skills load locally from this repository./ The installer gives every local
  agent every skill, the claude.ai set included, and turns off Claude Code's
  synced copies; changes reach claude.ai by uploading the built zip. One
  version is edited and tested locally, and Claude Code would otherwise list
  both copies.
- /Skills are concise and complete./ A skill holds every step and rule a model
  would otherwise get wrong, each stated once; adapting a third-party skill
  changes only what conflicts with the maintainer's rules. Once a skill loads,
  every token competes with the conversation, and vague guidance fails too.
- /New skills come from real runs, checked against primary sources./ The
  sources refuted several case-study claims (an SVG =sourceSize= multiplied by
  the pixel ratio counts it twice; a diff threshold of 40 let real shifts
  through). The runs added five rules to the workflow skills: full gates on the
  final commit, a generated file changed at its generator, tests on the current
  build, a check script trusted only after it catches a planted case, and
  slowness measured.
- /Scripts in skills stay light./ A script a skill runs uses the standard
  library plus at most one common package, and its tests run in CI without
  that package, so the skill works wherever it is installed.
- /Qt facts live in qt-quick./ The Qt facts and the Qt way to apply MVVM live
  in qt-quick, so clean-architecture stays language-neutral and reusable
  outside Qt.
- /The adapted learn skill is named tutor./ claude.ai keeps the name learn
  reserved for its built-in skill even when it is turned off.
- /as-built-docs reads code on the session's model./ Its mapping subagents run
  on the session's model, not a smaller one: the fact-check catches wrong
  facts but not missing ones, so a weaker reader's omissions would pass.

** What the skills teach

- /Every application gets every clean-architecture layer./ Domain, use cases,
  infrastructure, presentation and a composition root, with dependencies
  pointing inward and repository interfaces in the domain; a use case returns
  its result, and one that would only forward a call is left out only as a
  decision the project records. One structure in every project, as Martin,
  Evans, Fowler and Cockburn describe it, at the cost of heavier small apps.
- /UI threads never block; work moves through events./ event-driven-ui moves
  file writes, I/O and heavy work to long-lived workers whose results come
  back as events, and keeps one loop with asynchronous APIs when every handler
  fits the frame budget. It matches Chromium's, Android's, Apple's and Qt's
  threading guidance, and a separate skill loads when a UI freezes.
- /Diagrams use the nexenne palette in day and night./ Every PlantUML diagram
  includes the skill's =palette.iuml= and no other styling, the skill names
  neither the palette's origin nor any project, and groups are packages, not
  stereotypes. One file serves both themes, and a light fill without its text
  colour was unreadable in the dark preview.
- /As-built docs are written for people and synced, not rewritten./ Three
  documents, each opening with its own vocabulary and the big picture, under a
  word budget, with titled UML diagrams, lookup facts in an appendix, bugs left
  to code-audit and readability enforced by checks that fail; a rerun syncs
  from the recorded commit. Earlier generated docs were tedious through
  density.
- /As-built docs show the UI with rendered, annotated pictures./ Pictures come
  only from the real app driven to each state, each with a recipe and a
  numbered legend that a check matches against its markers; when the app
  cannot run, the user is asked and nothing is sketched. A description of an
  app includes what the user sees, and rendered pictures stay true to the
  code.
- /Code audits report only confirmed findings and ask about the rest./
  code-audit writes a local report of findings confirmed by a check that could
  fail, each with severity, confidence, =file:line= and evidence, keeps every
  doubt as a question for the user, and fixes nothing. False positives make
  people ignore a report.

** Git and licence

- /Agents outside Claude Code never push./ The guard blocks every push in
  Codex, Gemini CLI, Copilot CLI and Cursor, and force pushes and deletions in
  every tool. Outside Claude Code nothing asks before a push, so the maintainer
  pushes there.
- /No AI attribution in commits./ Commits and pull requests carry no
  =Co-Authored-By= or other AI trailer; the human committer owns every line
  ([[file:AI_DISCLAIMER.org][AI_DISCLAIMER.org]]).
- /MIT licence held by Nicolò Plebani (nexenne)./ Original work is MIT,
  Copyright (c) 2026 Nicolò Plebani (nexenne), with a =LICENSE.txt= in every
  skill; adapted third-party work keeps its licence and credits the changes.
  It is the maintainer's standard licence, compatible with reuse across his
  projects.
