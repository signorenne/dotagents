#+TITLE: Disclaimer on the use of AI code assistants
#+SUBTITLE: who answers for AI-assisted work in dotagents
#+OPTIONS: toc:nil num:nil ^:nil
#+STARTUP: showall

This file owns dotagents' accountability policy for AI-assisted work. The
agent-facing rules live in [[file:AGENTS.md][AGENTS.md]]; the workflow and gates in
[[file:CONTRIBUTING.org][CONTRIBUTING.org]]; the rules that bind in [[file:DESIGN.org][DESIGN.org]]; the documentation
map in [[file:docs/README.org][docs/README.org]].

AI code assistants are allowed in dotagents and can be valuable tools that help
improve productivity, explore solutions, and speed up development. Most of this
repository is itself written for AI agents: rules, skills, subagents and hooks.
Like any tool, the assistants must be used with understanding, care, and
professional judgment.

The person using an AI assistant is fully responsible for what they produce.
Every line of Python, JSON, Markdown, Org and skill text that is committed,
merged, or released is the responsibility of the developer who submits it,
regardless of whether it was written by hand, generated by AI, copied from
documentation, or adapted from another source.

AI suggestions are always reviewed, tested, and understood before they are
accepted. Developers verify correctness, security, maintainability, and
alignment with project standards: the format and text rules
=tools/validate.py= enforces, the tests, and the rules in [[file:DESIGN.org][DESIGN.org]]. A
skill or rule an agent drafted changes how every later agent works, so its
behavior is tried in a real session before it lands, or the commit says it was
not. "The AI wrote it" is not a valid explanation for introducing bugs,
vulnerabilities, or poor design decisions.

Think of an AI code assistant like a power tool in a workshop. A skilled
craftsperson can use it to work faster and achieve better results, but the
tool does not replace skill, knowledge, or responsibility. If a carpenter uses
an electric saw and cuts a piece incorrectly, the saw is not accountable, the
person operating it is. The same applies to AI-assisted development.

Use AI as an assistant, not as an autopilot. It can accelerate your work, but
you remain the engineer, the reviewer, and the person accountable for the
final result. Commit messages and pull requests carry no AI trailer
(=adapters/claude/settings.json= empties Claude Code's attribution): the
committer signs the change.
