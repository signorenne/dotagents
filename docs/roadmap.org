This file owns the state of the work: what works today, what is open, and the
rules proposed but not yet accepted. [[file:../DESIGN.org][DESIGN.org]] owns the design and the
rules that bind; [[file:../CONTRIBUTING.org][CONTRIBUTING.org]] owns the workflow.

* How status is kept

- =[ ]= open, =[-]= in progress, =[X]= done. A done item names the commit or
  the test that proves it when that is not obvious.
- Status is updated in the same commit as the change that moves it. No other
  doc carries status.
- An item dropped from the plan stays where it was with "(dropped: reason)"
  and is never deleted.
- A proposed rule waits under [[*Proposed rules][Proposed rules]] until the maintainer decides:
  accepted, it moves to DESIGN.org under Rules that bind; rejected, it stays
  here marked "(rejected: reason)".
- "Untested" means nobody has run the case; "unverified" means the claim comes
  from a source not yet checked against a primary one.

* Open

** Hooks and the guard

- [ ] Cursor's shell tool may be named =Shell= rather than =Bash=, so the
  guard's =Bash= matcher may not fire there. Untested.
- [ ] An empty hook reply may block in Cursor. Untested.
- [ ] Commands the guard still lets through, where the push rule rests on
  the agent: =gh api=, which can create pull requests, releases and refs
  through GitHub's REST API; a command passed as one string (=bash -c=,
  =env -S=, =flock -c=, =git submodule foreach=, the arguments after
  =parallel='s =:::=) and =eval=; aliases and scripts; the remote command of
  =ssh -o RemoteCommand=; and programs it does not know that run their
  arguments or a remote command (=autossh=, =mosh=, =numactl=, =faketime=).
- [ ] The field names inside Copilot's =toolArgs= for edits are undocumented;
  =after_edit.py= reads =path=, =file_text= and =new_str=, as its tests do.
- [ ] The compaction brief (=compact_brief.py=, Claude Code's =PreCompact=) is
  untested in a real session: whether the summary keeps what it asks for is
  unmeasured, and what Cursor does with the =PreCompact= entry it imports from
  =~/.claude/settings.json= is unchecked.
- [ ] Hook time budgets assume each tool's default timeouts: the session
  refresh keeps its notes listing and its git calls under 8 s and the
  after-edit hook bounds clang-format under 60 s. Untested outside Claude
  Code.
- [X] Codex runs =session_refresh.py= on =SessionStart= after =compact= or
  =resume=, as its hooks documentation describes
  (=test_codex_refreshes_the_session_after_a_compaction_or_a_resume= in
  =tests/test_install.py=). Untested in a real Codex session.
- [ ] In Claude Code a hook that crashes, times out or is missing lets the
  command run. ="onFailure": "block"= on the guard entry (Claude Code
  v2.1.295 or later, hooks docs) would block instead; the guard still exits 0
  on unreadable input. DESIGN.org owns the failure model, so this is the
  maintainer's call.
- [ ] A Claude Code =ConfigChange= hook could refuse a change to the user
  settings that removes =guard_bash.py=, so a session cannot drop its own
  guard. Low priority; untested.
- [ ] A =Stop= hook could report uncommitted work to the user
  (=systemMessage=) without blocking: blocking would push the agent to
  commit, which the global rules leave to the maintainer.
- [ ] A Claude Code status line could show the context used and the session
  cost (=context_window.used_percentage=, =cost.total_cost_usd=). Convenience
  only.

** Tools and platforms

- [X] Gemini CLI was replaced by Antigravity CLI (=agy=) for Google AI Pro,
  Ultra and free users on 18 June 2026; Gemini CLI stays for Code Assist
  Standard and Enterprise licences and paid API keys (Google Developers Blog,
  19 May 2026). The installer keeps the Gemini CLI adapter and adds one for
  Antigravity CLI, built from its hooks, skills, rules and customization
  discovery pages (=test_antigravity_*= in =tests/test_install.py= and
  =tests/test_hooks.py=).
- [ ] Antigravity CLI is untested in a real session. Its docs give no exit
  codes, so the guard answers with a JSON decision and exit 0.
- [ ] Antigravity CLI documents no reply that reaches the agent after an edit
  (a PostToolUse hook returns ={}=), so its after-edit hook formats C and C++
  but its dash report and its reformat notice stay on stderr; after a
  reformat, the agent's next edit may quote text that is no longer there. A PreToolUse hook that denies a write
  holding a dash, with the reason, would reach the agent; that is the
  maintainer's call.
- [ ] Antigravity CLI documents no event after a compaction or a resume
  (=SessionStart= fires for a new conversation), so it gets no session
  refresh.
- [ ] Antigravity CLI's custom agents (=~/.gemini/config/agents/<name>.md=,
  with their own frontmatter and tool names) are not generated yet.
- [ ] The docs give no fields for the chunks of Antigravity CLI's
  =multi_replace_file_content=, so the after-edit hook neither checks nor
  formats that edit.
- [ ] Antigravity CLI uses =~/.gemini= too, so on a machine with only
  Antigravity CLI the installer also detects Gemini CLI and writes its files;
  of those, Antigravity's docs list only =GEMINI.md= among the files it
  reads.
- [ ] The Codex rules file is untested in a real Codex session; Codex calls
  its rules experimental, and a prefix rule cannot match =git -C <dir> push=
  (the guard does).
- [ ] Codex ignores =sandbox_mode= in a custom agent file (its subagents
  docs), so the installer's read-only setting for =scout= has no effect there;
  dropping the field, or reducing scout's capabilities another way, is open.
- [ ] =gate-runner='s =omitClaudeMd= needs Claude Code v2.1.271 or later;
  what older versions do with the field is unchecked.
- [ ] =tools/validate.py= caps a skill body at 20,000 bytes as an estimate of
  the 5,000 tokens Claude Code keeps of each skill after a compaction; the
  byte-to-token ratio is unverified.
- [ ] Codex's default sandbox blocks =git commit=, so =implement= asks for
  approval there or leaves the step uncommitted and logged.
- [X] The installer writes Copilot CLI's files to =$COPILOT_HOME= when it is
  set, which replaces the whole =~/.copilot= path
  (=test_copilot_files_follow_copilot_home= in =tests/test_install.py=).
- [ ] Test whether claude.ai still caps skill descriptions at 200 characters;
  =tools/validate.py= enforces that limit for the claude.ai set and the
  overrides.
- [ ] The subagent copies the installer writes for Codex, Gemini CLI and
  Copilot drop the =model= field, so =scout= and =gate-runner= run on the
  session's model there; only Claude Code honours the cheaper models.
- [ ] =adapters/claude/settings.json= turns off the synced plugin
  =engineering@synced=; DESIGN.org records it, but no doc explains why.
- [ ] Both hooks accept =--tool cursor= and =after_edit.py= reads Cursor's
  own edit payload, but no installed configuration uses them: Cursor runs
  the Claude Code commands with =--tool claude=.
- [ ] Gemini CLI may load =AGENTS.md= twice on a machine set up by the
  installer: once through =context.fileName= and once through the
  =@AGENTS.md= import in =GEMINI.md=.
- [ ] Claude Code's OS sandbox (off by default; Linux needs bubblewrap and
  socat) would confine writes to the working folder and deny writes to
  =.git/hooks= and =.git/config=, independently of the guard. It changes daily
  work (network prompts, builds outside the folder), so try it for one session
  with =claude --settings= before deciding.
- [ ] A model map: which model and effort each role uses in each tool (main
  session, =scout=, =gate-runner=, =reviewer=). Today only Claude Code honours
  the subagents' =model= field (item above).
- [ ] Claude Code lists skill descriptions within about 1% of the context
  window and drops the least used ones when the list overflows; our
  descriptions total about 11,700 characters. On 13 November 2026 a large
  context session listed every description in full; a 200k session is
  unchecked. Check the Skills row of =/context= there before rewording a
  skill that fails to trigger; the fixes are =skillListingBudgetFraction=,
  name-only listing for rare skills, or shorter descriptions.
- [ ] Claude Code's auto memory overlaps each project's decision log and the
  notes in =.private/=: keeping it, limiting it or turning it off is the
  maintainer's decision.
- [ ] A =maxTurns= cap on =gate-runner= would bound its cost. Low value.
