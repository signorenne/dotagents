rules proposed but not yet accepted. [[file:../DESIGN.org][DESIGN.org]] owns the design and the
rules that bind; [[file:../CONTRIBUTING.org][CONTRIBUTING.org]] owns the workflow.

* How status is kept

- =[ ]= open, =[-]= in progress, =[X]= done. A done item names the commit or
  the test that proves it when that is not obvious.
- Status is updated in the same commit as the change that moves it. No other
  doc carries status.
- An item dropped from the plan stays where it was with "(dropped: reason)"
  and is never deleted.
- A proposed rule waits under [[*Proposed rules][Proposed rules]] until the maintainer decides:
  accepted, it moves to DESIGN.org under Rules that bind; rejected, it stays
  here marked "(rejected: reason)".
- "Untested" means nobody has run the case; "unverified" means the claim comes
  from a source not yet checked against a primary one.

- [X] Decisions of the claim check and the hidden-text check, reviewed and
  kept by the maintainer on 14 November 2026. The claim check counts as an
  edit an =Edit=, =Write=, =MultiEdit= or =NotebookEdit= call that did not
  fail, or a quiet or unknown shell command whose result records changed
  files, except edits of task notes (=.private/=), temporary files, the
  scratchpad and =~/.claude=, so a progress log written after the gates does
  not send the agent back. It counts as a known test run a test runner
  (=pytest=, =python -m unittest=, =go test=, =npm test= and the like, also
  through a launcher or =bash -c=), read from its summary lines or, when none
  matches, its exit status. A script or build target named test, gate, check
  or verify (=./run_tests.sh=, =make check=) is a known test run too, so a
  failing check script after the last edit sends the agent back. A build whose
  targets name no test (a bare =make=) is of unknown kind, since its default
  target may run tests. PowerShell commands are read with the Bash parser and
  the same program lists, so a PowerShell-only command such as =Get-ChildItem=
  is of unknown kind, and any =mcp__= tool after the last edit is a run of
  unknown outcome. The hidden-text check lets through an emoji's own
  presentation selector (one U+FE0E or U+FE0F right after a pictographic
  character) and a zero width joiner between two pictographic characters,
  reports a run of selectors from its second one, and reports keycaps (#
  U+FE0F U+20E3) and tag sequences (subdivision flags).
