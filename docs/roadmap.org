rules that bind; [[file:../CONTRIBUTING.org][CONTRIBUTING.org]] owns the workflow.

* How status is kept

- =[ ]= open, =[-]= in progress, =[X]= done. A done item names the commit or
  the test that proves it when that is not obvious.
- Status is updated in the same commit as the change that moves it. No other
  doc carries status.
- An item dropped from the plan stays where it was with "(dropped: reason)"
  and is never deleted.
- A proposed rule waits under [[*Proposed rules][Proposed rules]] until the maintainer decides:
  accepted, it moves to DESIGN.org under Rules that bind; rejected, it stays
  here marked "(rejected: reason)".
- "Untested" means nobody has run the case; "unverified" means the claim comes
  from a source not yet checked against a primary one.

* Open

- [ ] Cursor's shell tool may be named =Shell= rather than =Bash=, so the
  guard's =Bash= matcher may not fire there. Untested.
- [ ] An empty hook reply may block in Cursor. Untested.
- [ ] The guard does not inspect =git subtree push= or =gh pr create=.
- [ ] The field names inside Copilot's =toolArgs= for edits are undocumented;
  =after_edit.py= reads =path=, =file_text= and =new_str=, as its tests do.
- [ ] Hook time budgets assume each tool's default timeouts: the session
  refresh keeps its git calls under 8 s and the after-edit hook bounds
  clang-format under 60 s. Untested outside Claude Code.

* Proposed rules

- [ ] One source of truth in =~/.agents=, generated copies per tool.
  Instructions, skills, subagents and hooks have one source (=home/.agents=,
  installed as =~/.agents=); =install.py= links or generates each tool's files
  from it, and nothing is edited in a tool's own folder. Why: five agents read
  different file names and formats, and hand-kept copies drift. Proposed by an
  agent; revisit if the tools converge on one standard location for
  instructions, skills and subagents.
