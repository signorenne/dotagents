This file owns how the pieces work together once installed: the maieutic
method, the daily loop (which skill to run when), context hygiene, cost and
cache habits with how to measure them, the per-project layer and the setup
steps. [[file:pipeline.org][docs/pipeline.org]] owns the stages a change goes through from idea
to merge; [[file:../DESIGN.org][DESIGN.org]] owns how the pieces compose and install;
[[file:../README.org][README.org]] owns the quick start. The method is the same in every chat
and every project because claude.ai and every local agent read the same
global rules.

* Two-way maieutic method

- You question the agent Socratically ("why?", "what are you assuming?"): it
  answers that question, changes nothing unless asked, and shows evidence,
  assumptions and what would prove it wrong.
- The agent guides you on choices that are yours (scope, public API,
  architecture, rules): the decide skill establishes what is known, isolates
  the missing information, asks one question at a time with a recommended
  option and the consequence of each option, and records the decision after
  your explicit confirmation. Up to four independent, low-stakes questions may
  share one message.
- The agent questions its own work the same way: before relying on a claim
  (its own, yours, a document's, a subagent's, a test's) it tries to break the
  ones that matter with a check that could fail; rereading is not a check.
  Refuted assumptions go into the progress log and the handoff, and
  session-close turns those a rule should have prevented into proposed
  changes.
- When you ask to learn, the Learning section and the tutor skill give graded
  help and announce every check.
- Not maieutic toward you, by design: routine engineering inside an approved
  plan, plain questions, clear requests, and "decide" (the agent chooses with
  its recommendations and lists the assumptions).

The subagents keep the main conversation small: scout maps code and docs
read-only, gate-runner runs builds and tests and returns only verdicts and
first errors, reviewer reviews a finished change in a fresh context.

* Context hygiene

- One task per session; start a fresh session (Claude Code: =/clear=) between
  unrelated tasks.
- In Claude Code, after a compaction or a resume, the session refresh reminds
  the agent that its memory of the code is a summary, prints the real branch,
  changes and last commits, lists the newest progress and handoff files, and
  asks it to re-read the progress log. The other tools have no session start
  hook: ask for that re-read yourself.
- Specs, progress logs and handoffs live in =.private/= inside each repository
  (git-ignored); decisions live in the project's decision log.
- implement keeps =.private/progress/<slug>.<ext>= current after every step;
  how you review the agent decisions it marks =Review: pending= is in
  [[file:pipeline.org][docs/pipeline.org]].

* Cost and cache habits

In Claude Code every request sends the whole conversation again, and the
prompt cache serves the part that did not change at a fraction of the input
price. These habits keep that part intact:

- Pick the model and the effort at session start. Each model has its own
  cache, so a switch reads the whole conversation again uncached. A change of
  effort does too, except on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 or
  later with an API key or a subscription.
- Do not toggle plugins or MCP servers mid-task: when tools load upfront
  (tool search off or unavailable), a changed tool list rebuilds the cache.
- Compact at natural breaks, between tasks: a compaction replaces the
  conversation with a summary, which starts a new cache.
- =/clear= costs nothing: use it, not a compaction, when the next task does
  not need this conversation.
- To abandon a path, =/rewind= to the turn before it rather than compacting:
  the earlier part of the conversation is still cached.
- Keep the =model= field out of skills: a skill that names another model
  switches to it for that turn, uncached. =tools/validate.py= allows only
  =name=, =description= and =license=.

Source: Anthropic, [[https://code.claude.com/docs/en/prompt-caching][How Claude Code uses prompt caching]] (vendor documentation).

* Measure before and after

To tell whether a change to the setup (a shorter skill, a new hook, a rule
moved) saves tokens, measure sessions, not file sizes:

1. Keep the rest fixed: the same model and effort, the same Claude Code
   version, and the same kind of task.
2. In a fresh session, before the first prompt, run =/context=: it shows the
   fixed overhead every request carries (system prompt, tools, memory files)
   and the Skills row, the skill descriptions.
3. At the end of each session, before =/clear= resets it, run =/usage=: the
   Session block gives the tokens per model (input, output, cache read, cache
   write), and its =Prompt cache (main)= line the share of input served from
   the cache and the misses, with their likely cause. That line covers the
   main conversation only, not subagents.
4. Run five or more sessions on each side and compare the medians: single
   sessions vary too much to judge.
5. Compare billed-equivalent tokens, not bytes or raw token counts: weight
   each kind by its price relative to base input on the [[https://platform.claude.com/docs/en/about-claude/pricing][model's pricing page]]
   (on current models a cache read costs a tenth of an input token or less, a
   cache write 1.25 or 2 times as much, output 5 times). Bytes removed from a
   cached prefix save little; a change that causes cache misses can cost more
   than it saves.

Source: Anthropic, [[https://code.claude.com/docs/en/costs][Manage costs effectively]] (vendor documentation).

* Per project

Everything global works in every repository. Each repository needs its own
layer once: an =AGENTS.md= with the project's facts (commands, rules, where
files go), a decision log, an agent workflows doc, and =.private/= in
=.gitignore=. Run project-setup in the repository root to create or audit it.
Add a project skill only for a recipe you repeat that =AGENTS.md= does not
already describe.

* Setup

1. claude.ai: paste [[file:../home/.agents/AGENTS.md][home/.agents/AGENTS.md]] into Settings > General >
   Instructions for Claude, then upload the skill set
   ([[file:../claude-ai/README.md][claude-ai/README.md]]).
2. Linux or macOS: install Claude Code
   (=curl -fsSL https://claude.ai/install.sh | bash=), sign in with your
   claude.ai account, install any other agents you use, then run
   =python3 install.py --dry-run= and =python3 install.py= from this
   repository.
3. Cursor only: paste =~/.agents/AGENTS.md= into Settings > Rules > User Rules.
   Codex only: approve the hooks when it asks.
4. Check in Claude Code: =/memory=, =/skills=, =/agents=, =/hooks=, and that
   =git commit --allow-empty -m test --no-verify= is blocked.

After changing anything in this repository, run =python3 install.py= again,
and update the claude.ai copy of =AGENTS.md= or the uploaded skills when those
changed.
