This file owns the workflow for changing dotagents: the steps, the local
gates, CI, commit messages and the docs format. [[file:AGENTS.md][AGENTS.md]] owns where each
kind of change goes, the hard rules and the review checklist;
[[file:DESIGN.org][DESIGN.org]] owns the design and the rules that bind;
[[file:docs/skill-authoring.org][docs/skill-authoring.org]] owns how a skill is written and tested;
[[file:docs/pipeline.org][docs/pipeline.org]] owns the stages an agent's change goes through;
[[file:docs/README.org][docs/README.org]] maps every doc.

* Workflow

1. Start from [[file:AGENTS.md][AGENTS.md]], then load the docs [[file:docs/README.org][docs/README.org]] assigns to
   your role.
2. Work on a topic branch off =main=; agents never commit to =main= directly
   (global rules). One topic per branch.
3. Put the change in its owning place (next section), never as a second copy,
   and check it against the rules in [[file:DESIGN.org][DESIGN.org]]. A change that conflicts
   with one stops and states the conflict.
4. Run the three local gates, then =python3 install.py --dry-run= and
   =python3 install.py=. Test a behavior change in a real agent session when
   the maintainer asks for it; whether that test was done is noted in the
   task's progress log or in the pull request, never in a commit, which has
   no body. A change to =home/.agents/hooks/guard_bash.py= also runs
   =python3 tools/guard_replay.py --base main= before it lands
   ([[file:DESIGN.org::#guard-replay][DESIGN.org#guard-replay]]): the maintainer judges each command the
   report lists as newly blocked, and the progress log records the counts
   and the judgement.
5. Land the work as small commits, each one logical change that passes the
   gates on its own. Agents never push: the maintainer
   reviews the branch, gives the go to land it, and pushes
   ([[file:docs/pipeline.org][docs/pipeline.org]]).
6. After the change lands: paste =home/.agents/AGENTS.md= into claude.ai again
   when the global rules changed, and upload the changed claude.ai skills
   ([[file:claude-ai/README.md][claude-ai/README.md]], "Update a skill").

A new rule, or a change to one, is the maintainer's call: propose it, and
move it into [[file:DESIGN.org][DESIGN.org]] only after the maintainer
accepts it.

* Where changes go

[[file:AGENTS.md][AGENTS.md]] owns where each kind of change goes (Where changes go) and the
rules every change keeps, the license included (Hard rules). Read it before
the first edit; this file does not repeat it.

* Local gates

Before each commit, run validate and the test module that covers the change (for
example python3 -m unittest tests.test_hooks.ClaimCheck); run all three on the
last commit of a branch, or of a series of commits on main, before it lands:

#+BEGIN_SRC sh
python3 tools/validate.py              # skill and subagent format, text rules, script syntax
python3 -m unittest discover -s tests  # hooks, installer, tools and skill scripts
python3 tools/build.py                 # claude.ai zips and the project kit into dist/
#+END_SRC

When a gate fails because the change is wrong, fix the change: no skipped,
deleted or loosened tests and no hook bypass without the maintainer's
approval.

* CI

GitHub Actions ([[file:.github/workflows/ci.yml][.github/workflows/ci.yml]]) runs the =check= job on every
push and pull request, in three configurations:

| Runner          | Python | Notes                                            |
|-----------------+--------+--------------------------------------------------|
| =ubuntu-latest= |    3.9 | the oldest Python the installer supports         |
| =ubuntu-latest= |   3.12 | with Pillow, which the skills' image scripts use |
| =macos-latest=  |   3.12 | the other platform the installer supports        |

Each runs the three local gates in order (validate, test with =-v=, build).
Pillow is installed in one job only, so the other two prove the tests run
without it.

* Commit messages

The subject line is =type(scope): description=, and it is the whole message:

- =type= is the kind of change (table below).
- =scope= names the area: =skills=, =agents=, =hooks=, =install=, =validate=,
  =docs=, =design=, =workflow=, =github=, =project= for the root docs that
  describe the project as a whole, or =repo= for a repository-wide change.
- =description= is one sentence: lower case, imperative, no trailing period,
  no em or en dash.
- No body. If a change cannot be described in one sentence, split it into
  smaller commits.
- No =Co-Authored-By= and no other AI trailer: the committer signs the change
  ([[file:AI_DISCLAIMER.org][AI_DISCLAIMER.org]]).

| type     | for                                     |
|----------+-----------------------------------------|
| feat     | a new skill, subagent, hook or behavior |
| fix      | a bug fix                               |
| refactor | restructuring, no behavior change       |
| test     | tests only                              |
| docs     | documentation only                      |
| ci       | CI configuration                        |
| chore    | tooling and housekeeping                |

#+BEGIN_SRC text
feat(skills): add the isolated-work skill
fix(hooks): block every push and publish in every tool
docs(design): record that no agent pushes or publishes
#+END_SRC

Once a clone enables it (=git config core.hooksPath .githooks=, as
[[file:README.org][README.org]] says), =.githooks/commit-msg= checks each message and rejects one
whose type is not in the table, whose scope is missing or not in lower case,
whose subject does not read =type(scope): description=, or whose description
is empty; a subject with an upper case letter (identifiers too), a trailing
period or an em or en dash; any line below the subject; and, below the
subject, an AI trailer (=Co-Authored-By=, =Generated with= or =by=,
=Assisted-by=, the Anthropic noreply address). So a merge or revert message
is rejected too: write a revert as a typed subject. A =fixup!= or =squash!=
subject passes when the rest of it does, and comment lines are not part of
the message. On a rejection it says what to write instead. The imperative
mood stays the author's to keep.

* AI code assistants

Allowed, with full accountability for every line submitted. Agent and human
work starts from [[file:AGENTS.md][AGENTS.md]], then the role matrix in [[file:docs/README.org][docs/README.org]].
Agents keep specs, progress logs and handoffs under the git-ignored =.private/=.
Commits carry no AI trailer. The policy is [[file:AI_DISCLAIMER.org][AI_DISCLAIMER.org]].

* Docs

Prose docs are Org mode (=.org=). Markdown stays where a tool reads the file:
=AGENTS.md=, the bridges =CLAUDE.md=, =GEMINI.md= and
=.github/copilot-instructions.md= (which point to =AGENTS.md= and duplicate no
rule), the global rules in =home/.agents/AGENTS.md=, every skill file, and
=claude-ai/README.md=, which =tools/build.py= ships in the claude.ai bundle.

An Org doc opens with its header (=#+TITLE=, =#+SUBTITLE=, =#+OPTIONS=,
=#+STARTUP=) and a paragraph that says what it owns. Use sentence-case
headings, =code= markup for identifiers, commands and paths, =[[file:...]]=
links, prose wrapped near 80 columns and aligned tables. No em or en dash
anywhere (=tools/validate.py= fails on one), no backticks in Org prose, no
marketing words and no minimizers. Register a new doc in
[[file:docs/README.org][docs/README.org]] and a new term in [[file:docs/glossary.org][docs/glossary.org]].
