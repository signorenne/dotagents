working-memory floor for agents changing this repository.

* What it is

One setup for every coding agent and for claude.ai: global rules, skills,
subagents and safety hooks, installed for Claude Code, Codex, Gemini CLI,
Antigravity CLI, GitHub Copilot CLI and Cursor from a single source.

What it gives every session, in chat or in a repository:

- The same global rules everywhere (priorities, sufficiency, evidence, a
  terse register, no em dashes), including a Socratic method: you question
  the agent, the agent settles your decisions with you through an assumptions
  table and only the questions that change them, and it tries to refute its
  own assumptions with checks that could fail.
- One method for changes in a repository ([[file:METHOD.org][METHOD.org]]): the build skill
  investigates, picks a lane (direct, quick or full) by the consequence of a
  mistake, keeps the whole state in one plan file any later session resumes
  from, stops only for a closed list of reasons and records every other
  choice as a ruling for your review. Around it: design, close, decide,
  branch-review, gates, project-setup, and skills for documentation, design,
  code quality, coordination and Qt; the full list is under [[*Skills][Skills]]. In
  Claude Code, path rules point QML, PlantUML and test files to their skills.
- Three subagents that keep the main context small: =scout= (read-only
  mapping), =gate-runner= (builds and tests, returns only verdicts) and
  =reviewer= (independent review).
- Hooks that block git gate bypasses and every push or publish (no agent
  pushes: the maintainer reviews and pushes), flag em and en dashes, check
  Python, JSON and TOML syntax and run clang-format on the C and C++ lines an
  edit changed. In Claude Code and Codex, on a new session, a clear, a
  compaction or a resume, they print the plan file's state (and, after a
  compaction or a resume, the real git state), and when the agent ends its
  turn they record the branch's commits in the plan's log without a model
  turn. Gemini CLI, Copilot CLI and Cursor get the plan's state at session
  start too. In Claude Code they also tell the compaction summary what resuming
  needs, suggest clearing a large context after a step's commit, remind the
  agent to change approach when a shell command fails the same way three
  times, and send it back once if its final message says the tests pass
  with no passing run after its last edit.
- A claude.ai skill set (decide, tutor, debugging, verification, tests,
  scoping, editing, research, decisions, handoffs, prompts), installed locally
  from this repository for every agent too.

* Install

#+BEGIN_SRC sh
git clone https://github.com/signorenne/dotagents.git ~/dotagents
cd ~/dotagents
python3 install.py --dry-run   # shows every change, touches nothing
python3 install.py             # installs for the agents found on this machine
#+END_SRC

The installer detects the agents present (=~/.claude=, =~/.codex=, =~/.gemini=,
=~/.gemini/antigravity-cli=, =~/.copilot= or =$COPILOT_HOME=, =~/.cursor= or
their commands on =PATH=), moves every file it replaces to
=~/.agents-backup/<timestamp>/=, and is safe to run again: a second run changes
nothing. =--tools claude,codex= picks the agents explicitly. It needs only
=python3= (3.9 or later) and runs on Linux and macOS (on macOS,
=xcode-select --install= provides =python3= and =git=). [[file:DESIGN.org][DESIGN.org]] lists
what each agent gets.

Every file it writes is recorded with its hash in
=~/.agents/.dotagents-manifest.json=: a later run never overwrites a file you
changed by hand (=--force= backs it up and replaces it), removes what a newer
version no longer installs, and =python3 install.py --uninstall= removes what
it installed and nobody changed. =--personal DIR= adds a personal layer (lines
appended to the global rules, Claude Code settings of your own; this
repository's =personal/= is the maintainer's), and =--target DIR[:RULES]=
links the skills and the global rules into the folder of a tool the installer
does not describe yet (OpenCode, Kimi, Goose, Qwen Code, Pi); both are
recorded and applied again on later runs.

Claude Code users can instead install the packs as plugins, with no clone:

#+BEGIN_SRC sh
claude plugin marketplace add signorenne/dotagents
claude plugin install dotagents-method@dotagents   # also: dotagents-craft, dotagents-docs, dotagents-chat
#+END_SRC

The method pack carries the flow skills, the three subagents, the hooks and
the global rules (printed by a session-start hook); it does not set Claude
Code's permission rules or attribution settings, which only =install.py=
writes. Use one way or the other, not both.

Then:

1. claude.ai: paste [[file:home/.agents/AGENTS.md][home/.agents/AGENTS.md]] into Settings > General >
   Instructions for Claude, and upload the skill set as described in
   [[file:claude-ai/README.md][claude-ai/README.md]].
2. In any repository, run =project-setup= once to give it its =AGENTS.md=,
   the bridges and the project docs (vision, design, contributing, a docs
   map, a decision log and agent workflows).

The full guide, including the daily loop and the maieutic method, is
[[file:docs/workflow.org][docs/workflow.org]].

* Update

#+BEGIN_SRC sh
cd ~/dotagents
git pull                       # or: git am <file>.patch
python3 install.py --dry-run
python3 install.py
python3 install.py --audit     # what in the agents' folders is not from here; changes nothing
#+END_SRC

Then, only for what the update touched: paste =home/.agents/AGENTS.md= into
claude.ai again, and upload the changed claude.ai skills
([[file:claude-ai/README.md][claude-ai/README.md]], "Update a skill").

The installer removes what an update dropped when its manifest recorded it
and nobody changed it since, and the hook entries of a script it renamed;
[[file:DESIGN.org::*Install model][DESIGN.org, Install model]] has the details. =python3 install.py --audit=
lists what in the agents' folders does not come from here.

To change the setup itself, run Claude Code (or any agent) in this repository:
[[file:AGENTS.md][AGENTS.md]] says where each change goes and which checks to run, and
[[file:CONTRIBUTING.org][CONTRIBUTING.org]] holds the full workflow. Enable the commit message check
once per clone, before the first commit:

#+BEGIN_SRC sh
git config core.hooksPath .githooks   # .githooks/commit-msg checks each message
#+END_SRC

* Skills

Every agent gets every skill. In Claude Code, Antigravity CLI, Copilot and
Cursor a skill runs as =/name=, in Codex as =$name=; Gemini CLI activates one
when asked in words.

** Repository workflow

[[file:METHOD.org][METHOD.org]] states the method these skills apply.

- [[file:home/.agents/skills/decide/SKILL.md][decide]] : settles a choice that belongs to you, from an assumptions table
  and only the questions that change it, then records it.
- [[file:home/.agents/skills/build/SKILL.md][build]] : builds one change in its lane (direct, quick or full), from the
  plan file to the triaged review, resumable from that file in any session.
- [[file:home/.agents/skills/design/SKILL.md][design]] : turns a feature too large for one plan into a design and its
  ordered plans, checked by an independent agent, without writing code.
- [[file:home/.agents/skills/branch-review/SKILL.md][branch-review]] : reviews the current branch through the =reviewer= subagent and
  returns findings ranked by severity.
- [[file:home/.agents/skills/gates/SKILL.md][gates]] : runs the project's documented gates through =gate-runner= and
  reports only verdicts and the first errors.
- [[file:home/.agents/skills/close/SKILL.md][close]] : brings the plan files up to date, settles decisions and rulings,
  drafts lessons, and names the next action for a fresh session.
- [[file:home/.agents/skills/project-setup/SKILL.md][project-setup]] : sets up or audits a repository's =AGENTS.md=, bridges
  and project docs, from vision to agent workflows.

** Documentation and design

- [[file:home/.agents/skills/as-built-docs/SKILL.md][as-built-docs]] : asks which documents to write, where to save them, how
  to run the app for its screenshots and the scope, then writes a knowledge base, a manual test
  guide and a developer guide from the code, fact-checked and synced when the
  code changes.
- [[file:home/.agents/skills/architecture-doc/SKILL.md][architecture-doc]] : builds the requirements and the architecture of a new
  system or major component (EARS, arc42, C4, ADRs, an ATAM-style evaluation).
- [[file:home/.agents/skills/plantuml-diagrams/SKILL.md][plantuml-diagrams]] : draws PlantUML diagrams that read at a glance, in the
  bundled day and night palette, checked by rendering.
- [[file:home/.agents/skills/clean-architecture/SKILL.md][clean-architecture]] : keeps an application in clean architecture with
  MVVM, with dependencies that point inward and are checked by the build.
- [[file:home/.agents/skills/notes-from-work/SKILL.md][notes-from-work]] : turns what a session found (a bug's cause and fix, a
  workaround, a technique) into checked notes in the user's knowledge vault,
  landed after the user approves them.

** Code quality

- [[file:home/.agents/skills/code-audit/SKILL.md][code-audit]] : writes a local report of confirmed security issues, likely
  bugs and smells, with every doubt kept apart as a question.
- [[file:home/.agents/skills/mechanical-changes/SKILL.md][mechanical-changes]] : carries out one behavior-preserving change across
  many files (a rename, a migration, a codemod) in shards that build alone.

** Coordination

- [[file:home/.agents/skills/parallel-agents/SKILL.md][parallel-agents]] : runs several agents writing at once in one
  repository, each in its own worktree, and lands each branch on a commit
  that passed the gates.
- [[file:home/.agents/skills/isolated-work/SKILL.md][isolated-work]] : runs a complex or risky change in
  its own worktree and branch, keeps it for review, lands it by rebase and
  fast-forward on the maintainer's go, and removes the worktree and the branch.

** Qt and UI

- [[file:home/.agents/skills/qt-quick/SKILL.md][qt-quick]] : Qt 6 Quick and QML facts agents get wrong, and the Qt way to
  apply clean MVVM.
- [[file:home/.agents/skills/precise-ui-changes/SKILL.md][precise-ui-changes]] : makes visual UI fixes rendered and measured at
  device pixels, and proves with a diff check that nothing else moved.
- [[file:home/.agents/skills/event-driven-ui/SKILL.md][event-driven-ui]] : designs and fixes event-based concurrency so a UI or
  render thread never blocks.

** The claude.ai set

Uploaded to claude.ai and installed locally for every agent too. decide joins
the set through [[file:claude-ai/overrides.json][claude-ai/overrides.json]], with a shorter description.

- [[file:claude-ai/skills/tutor/SKILL.md][tutor]] : tutors toward real understanding: diagnosis first, graded help,
  one step per turn.
- [[file:claude-ai/skills/scoping-before-building/SKILL.md][scoping-before-building]] : asks only the question that changes the
  result before building.
- [[file:claude-ai/skills/systematic-debugging/SKILL.md][systematic-debugging]] : diagnoses a failure from evidence before any fix.
- [[file:claude-ai/skills/verifying-before-claiming-done/SKILL.md][verifying-before-claiming-done]] : checks the evidence before a completion
  claim and reports what was and was not verified.
- [[file:claude-ai/skills/trustworthy-tests/SKILL.md][trustworthy-tests]] : writes and reviews tests that can fail, never
  weakened to pass.
- [[file:claude-ai/skills/minimal-editing/SKILL.md][minimal-editing]] : makes the smallest complete change and shows only what
  changed.
- [[file:claude-ai/skills/efficient-research/SKILL.md][efficient-research]] : decides when and how much to search, primary
  sources first, and labels what is sourced, inferred or unknown.
- [[file:claude-ai/skills/decision-analysis/SKILL.md][decision-analysis]] : compares products, tools or vendors on your criteria
  and commits to a recommendation.
- [[file:claude-ai/skills/context-handoff/SKILL.md][context-handoff]] : writes a self-contained brief to continue in another
  chat, session or model.
- [[file:claude-ai/skills/prompt-optimizer/SKILL.md][prompt-optimizer]] : rewrites prompts and agent instructions to be
  specific, checkable and free of filler.
- [[file:claude-ai/skills/atomic-notes/SKILL.md][atomic-notes]] : writes notes and explanations the Zettelkasten way, one
  idea per note linked under a hub, facts checked, and reorganizes existing notes.
